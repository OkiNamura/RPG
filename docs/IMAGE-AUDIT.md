# Аудит image-модулей

Дата: 2026-11-04.

## Что уже есть

### Локальный image-worker

- Unsloth Studio: `http://127.0.0.1:8888`.
- Модель: `Qwen-Image-2.1-Turbo-GGUF`, загружена.
- Нативный endpoint `/api/inference/images/generate` умеет:
  - `reference_images`;
  - `negative_prompt`;
  - width/height;
  - steps/guidance.
- OpenAI-совместимый `/v1/images/generations` референсы не понимает.
- ControlNet: `qwen-union` (canny/depth/pose/passthrough).
- Семейство `qwen-image-edit` доступно.
- Локальных LoRA для Qwen нет.

### Python

До аудита: Pillow, numpy.

Установлено:

- `opencv-python-headless` 5.0.0;
- `imagehash` 4.3.2.

Не установлено:

- torch;
- open_clip;
- insightface/ArcFace;
- onnxruntime.

Решение: тяжёлые модули не ставить, пока не доказана необходимость. Для семантической проверки сцены достаточно VLM API; для кропов/лиц/хешей — cv2/imagehash.

### Node

Runtime-зависимостей для картинок нет. Playwright/typescript — dev.

## Чего не хватает в пайплайне

- визуальной библии персонажа;
- контракта сцены (сейчас — последние 900 знаков прозы);
- именованных референсов (сейчас до 3 без имён);
- seed;
- проверки результата;
- retry по QA;
- UI-инспектора.

## Вывод

Проблема не в отсутствии «плагина для рисования». Проблема в том, что иллюстратору дают сырую прозу и слишком мало структурированных данных о сцене.

Первый фикс — не новый модуль, а:

1. визуальная библия;
2. контракт сцены;
3. именованные референсы;
4. QA-проверка.

Дополнительные модули подключать только после теста этих четырёх.
