# plan: Очередь B: память rev2

ВЕРДИКТ: НЕ ОК

**Блокеры:**

1. **Место `memory.recall` в контексте не задано, а прямое прочтение плана сжигает кэш конспекта на каждом ходу.**
   - Где: в плане сказано «Recall — отдельный `memory.recall` после истории». Сразу после истории в `src/core/context.ts:334-342` стоит сегмент `conspect`, и он размером до 24 000 символов (`CONTEXT_SUMMARY_LIMIT`, `context.ts:87`). Дальше идут `lore.top`, `lore.history` и `lore.after` (`context.ts:345-356`), затем `state`.
   - Почему ломает: набор recall меняется почти каждый ход. Если поставить его между историей и `conspect`, кэш провайдера каждый ход теряет блок до 24k символов. Это та же проблема, которую чинили в A6a. В CONTEXT.md «фиксированный порядок контекста» указан в разделе «Что нельзя ломать». Блокер 2 прошлого ревью (`docs/reviews/2026-11-06T22-03-45-plan.md:13-17`) прямо просил указать конкретный слот, а в rev2 написано только «после истории».
   - Как исправить: явно указать слот `memory.recall`. Он должен стоять после `lore.after` и перед `state`. Порядок закреплённых записей в блоке `memory` тоже нужно задать детерминированно: сначала `importance`, потом `createdTurn`, потом `id`.
   - Как проверить: сделать два хода с одинаковыми закреплёнными записями и разным набором recall. Хэши сегментов от `static` до `conspect` должны совпасть. Этого теста в списке плана нет.

**Риски:**

- **Сохранение не описано.** Сейчас `persist` (`server.ts:1989-2003`) пишет только `memory: session.memory`, загрузка читает только `saved.memory` (`server.ts:1915`). Если не добавить `memories` в `SavedCampaign` (`storage.ts:88`), в `persist` и в загрузку, записи пропадут после рестарта сервера и после `reset`: он делает `sessions.delete(id)` (`server.ts:4187`), и сессия перечитывается из файла. Нужен тест: добавить запись → `sessions.delete` → `getSession` → запись на месте.
- **`restart` не описан.** Он обнуляет `session.memory` (`server.ts:4200`). Про `memories` ничего не сказано. Если их не трогать, новое прохождение начнётся с закреплёнными фактами старого, то есть со спойлерами. Это решение за пользователем, но в плане его нужно зафиксировать и покрыть тестом.
- **Ветки ведут себя по-разному.** Ветка сохраняет и восстанавливает строку `memory` (`server.ts:3422`, `3437`), а записи на уровне сессии останутся общими для всех веток. Факт из ветки A окажется в ветке B. Это нужно явно записать как решение. В тестах сейчас есть только undo, а нужны ещё regenerate (`server.ts:3655`) и загрузка ветки (`server.ts:3435`).
- **`source: 'agent'` без механизма.** Агент в rev2 записи не создаёт, а если бы создавал, то на уровне сессии его записи переживали бы undo. Тогда факты отменённого хода оставались бы в контексте. Это противоречит прошлому ревью: записи агента должны откатываться вместе с ходом. Либо убрать `'agent'` из enum в этой итерации, либо описать хранение записей агента в `GameState` с откатом.
- **Ключи для recall не указаны.** Не сказано, с чем сравниваются ключи: только ввод игрока или ещё место и последние ответы, как в `pickLore`. Сопоставление по ключам уже есть в `src/core/lore.ts:48` (`activateLore`) и `:104` (`matchLore`), второе писать не нужно.
- **Нет правила на 9-ю закреплённую запись.** Лимит блока 8/4000, а `pin` в API ничем не ограничен. Непонятно, вытесняется ли запись молча (и какая) или API отвечает 400/409. Предлагаю отклонять в API, чтобы закреплённая игроком запись не терялась незаметно.
- **Общий бюджет памяти.** Строка `session.memory` до 4000 (`server.ts:3900`), плюс 4000 на закреплённые, плюс 3000 на recall — до 11k символов поверх лора (6000). Общего лимита по-прежнему нет. Риск из прошлого ревью не закрыт.
- **Инспектор после рестарта.** `persist` сохраняет только `lore: session.lastLoreReport` (`server.ts:1966`). Отчёт по recall и вытесненным записям нужно сохранять так же, иначе после перезапуска инспектор пустой.
- **Роут.** `memory-entry` нужно добавить в regex `campaignMatch` (`server.ts:3449`), иначе ответ 404. Это мелочь, но тест на API её поймает.
- **PWA.** В `src/web/sw.js:3` версия `omika-shell-v54`. Если меняются `app.js` или `style.css`, версию нужно поднять, иначе на мобильном останется старая оболочка без меню «Память».
- **Модалка.** Должна использовать существующий механизм: Esc, фон, свайп вниз, «Назад», фокус-трап (CONTEXT.md, раздел UI). Нужен прогон a11y.
