# Контекст проекта

Обновлено: 2026-11-07 (сверено с кодом — Claude, read-only, без прогона).  
Это краткая карта проекта для ревьюера. Не ТЗ и не роадмап: только то, что уже решено и что важно не сломать.

## Что это

Текстовая RPG в браузере: ведущая модель пишет сцену, сервер хранит типизированное состояние и применяет изменения детерминированно.

Не чат с карточкой персонажа. Основная ценность — состояние мира, последствия и управляемая память.

## Стек

- Node.js ≥ 22.6, нативный TypeScript/ESM.
- Один HTTP-сервер: статика + API + SSE.
- Нет runtime-зависимостей.
- PWA: service worker, кэш оболочки.
- SQLite: поиск, снапшоты, трассы.
- JSON кампании — источник истины.
- Клиент — ванильный JS, hash-роутер, без фреймворка.

## Поток хода

Фактический (server.ts + core/turn.ts):

```text
pickLore            — World Info по ключам из ввода/места/последних ответов
pickNotes           — кубик (если включён) + скрытая проверка КАЖДЫЙ ход
augmentFeatureNotes — векторная память/recall, Director (LLM-вызов), групповая сцена, «жёсткая сцена»
runTurn             — контекст → ведущий (stream)
                      → пустой ответ: 1 повтор
                      → повтор действия (>0.72): директива, без второго вызова
                      → повтор ответа (>0.82): ещё 1 полный вызов ведущего
                      → дельта → +1 час, если ведущий не сдвинул время → critic → лог
afterTurn           — repair прозы
                      → [агент состояния ‖ суммаризатор раз в 3 хода] параллельно
                      → социальная реакция → revive
                      → цель времени → сцена (stalls) → тик мира
                      → пол/потолок времени (дорога, макс. скачок, без отката)
                      → страховка обещаний → снапшот → трасса → векторы → сохранение
```

Цель времени ставится после агента состояния, чтобы он не переписал выбор игрока.

Подготовка хода вынесена в `prepareTurn` (`pickLore → pickNotes → augmentFeatureNotes → timeTargetNote → numericSnapshot`), её используют turn, stream, regenerate и edit. `afterTurn` общий: агент состояния, время, сцена, снапшот. `turnOptions` в снимке хранит dice/focus/timeTarget.

## Контекст

Фактический порядок (`buildContext`, context.ts):

```text
static → memory → conspect.frozen
→ history (лог сообщениями) → conspect summary
→ lore.top → lore.history → lore.after
→ state → lore.depth → notes → turn
```

Задумка: динамика в конце ради кэша провайдера (кэшируется общий префикс). Динамический лор перенесён после истории: смена набора записей больше не должна сжигать кэш самого большого блока. Частоту смены ещё нужно замерить.

История: окно `windowTurns = 24` (48 сообщений), сдвиг блоками по 20 сообщений.

Пределы: summary режется до 65 000 символов (`trimSummary`), вытесненные арки — в `arcArchive` (до 100). Лор — до 8 записей / 6000 символов. `renderState` имеет компактный режим для ведущего (A3) и полный для агента состояния.

## Время

- Жёсткого расписания уроков нет.
- Явная длительность игрока приоритетна.
- Обычное действие не превращается в сутки.
- Время не откатывается.
- Ожидание не вызывает скрытых скачков.
- Сцена может закрыться, но не по таймеру.

## Сцена

В состоянии есть:

```text
scene {
  id, startedTurn, updatedTurn, place,
  participants, goal, lastBeat, stalls
}
```

- смена места начинает новую сцену;
- `participants` — только явно присутствующие;
- повтор действий увеличивает `stalls`;
- при 2+ `goal` = «сцена топчется: нужен новый факт» (`updateSceneCheckpoint`);
- повтор ответа ведущего перегенерируется.

## Состояние

Ключевые сущности:

- время, место, погода, календарь;
- герой, пати, NPC;
- предметы, деньги/валюты;
- фракции и нормы;
- репутация;
- фронты и часы;
- квесты, события, обещания;
- скрытые факты;
- сцена;
- рамка мира;
- лог.

Инварианты:

- `turn` только растёт;
- время не откатывается;
- деньги/предметы не уходят в минус;
- `present === true` — единственный признак присутствия в кадре;
- норма без id игнорируется;
- закрытые арки конспекта не перегенерируются.

## Нормы и фракции

- Нормы — данные: id, подпись, вес, internalized.
- У фракции свои веса.
- Один поступок может дать разные последствия разным фракциям.
- Репутация: общая и по фракциям.
- Свидетели влияют на отношение и дебаффы.
- Без свидетелей публичный дебафф не ставится, создаётся скрытый факт.

## Мир

- Фронты создаются из фракций.
- Прогресс двигается детерминированно.
- На давление влияют отношение фракции, репутация и события.
- При 25% создаётся квест.
- При 50% — событие линии NPC из `worldStory`.
- При 100% фронт завершается.
- Часы квестов могут провалить квест.
- Отношения фракций строятся по совпадению норм.

## Изображения

- Промт сцены собирается из контракта, а не из одной прозы.
- В кадр попадают только `present === true`.
- Посторонние люди запрещены.
- Жанр мира имеет приоритет над стилем иллюстратора.
- Современный мир блокирует фэнтези-элементы.
- Действие игрока входит в промт раньше прозы.
- Identity-seed стабилен для персонажа.
- Лицо держится по мастер-листу/портрету.
- Картинки идут через очередь, ошибка кадра не ломает ход.

## UI

- Мобильная и десктопная раскладка.
- Модалки закрываются кнопкой, фоном, Esc, свайпом вниз и системным «Назад».
- Фокус-трап, возврат фокуса.
- Свайп вправо — назад на списках.
- Pull-to-refresh только на списках.
- История по 50 сообщений, старые по 50.
- Кэш кампании и индикатор загрузки.

## Принятые решения

1. JSON — источник истины, SQLite — индекс/снапшоты/трассы.
2. Не вводить жёсткое расписание уроков и сцен.
3. Нормы и мораль — данные мира, не хардкод в движке.
4. Жанр изображения — из мира, не из ползунка интенсивности.
5. Ползунок уровня задаёт только интенсивность, не жанр.
6. В кадр попадают только явно присутствующие.
7. Старые кампании нормализуются, данные не удаляются.
8. Перед миграциями — бэкап.
9. Мелкие фиксы без протокола; крупные задачи — короткая запись в `PAIRING.md`.
10. N4, VPS и пентест не трогаются без отдельного решения.
11. Карта вырезана из активного UI в архив. В коде остались `openMapModal`, `side-map` и старый рендер — это хвосты, при переносе их не возвращать.

## Спорные/неподтверждённые пункты

- **Карта:** решение — вырезана в архив. Хвосты: `app.js:229, 3689, 5260, 6145`, `index.html:30`, `core/map.ts`, неиспользуемый импорт `server.ts:15`. Вычистить, а не восстанавливать.
- **Бюджет контекста:** в контексте summary режется до 24 тыс. символов, общий лимит 25 тыс. токенов только флагируется в инспекторе. История и notes не режутся; жёсткое вытеснение отложено.
- **Director:** подтверждено — отдельный LLM-вызов КАЖДЫЙ ход, если включены `storyDirector` и `director.enabled` (`server.ts:1332`). В ТЗ — «не каждый ход».
- **Память:** единый конспект + векторный поиск; трёхуровневой памяти (persistent/cascaded/retrievable) пока нет.
- **TTS/эмоции/импорт карточек** не реализованы.

## Известные расхождения (найдено по коду 2026-11-07, не прогоном)

1. **Присутствие.** Инвариант — `present === true`. Director, групповая сцена и `updateSceneCheckpoint` исправлены на `=== true`. Остались расхождения: `social.ts` (свидетели) и `app.js` используют `!== false`. Картинки — правильно, `=== true`.
2. **Фракции.** Дублирование в `renderState` убрано: один блок. В режиме `gm` состав показывается только если кто-то из состава в сцене; в режиме `agent` — всегда, чтобы агент не затирал состав.
3. **state без лимитов.** Для ведущего включён компактный режим: отсутствующие NPC без `mind`, лимит 8; квесты — все active/frozen + 3 закрытых; факты/обещания — 12/8 + счётчики. Агент состояния получает полный state. Нужен замер размера после A3.
4. **Двойной вызов ведущего.** Исправлено: повтор действия добавляет директиву, но второй вызов только при повторе ответа (`similarity > 0.82`). Стоимость повторного вызова учитывается.
5. **Regenerate/edit.** `turnOptions` добавлены в снимок и используются: regenerate сохраняет dice/focus/timeTarget; edit берёт dice/focus, но цель времени выводит из нового текста. `prepareTurn` выделен и используется всеми путями; роль finish выполняет общий `afterTurn`.
6. **Суммаризатор раз в 3 хода**, а не `summarizeEvery = 10` (это поле управляет только механическими арками, когда агент выключен).
