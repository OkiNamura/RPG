# Аудит проекта Omika

Без изменений security/цензуры. Не трогать данные кампаний.
Каждый этап: проверка → Claude review плана/диффа → фикс → тесты.

## Этап 1. Баги

- `tsc --noEmit`.
- unit/memory/director/world/context-order/events.
- UI 42/42, a11y.
- content-test с авторизацией.
- Поиск: TODO/FIXME, пустые catch, неиспользуемые импорты, `any`, битые `await`,
  `undefined` в пользовательских сообщениях.
- Claude: ревью списка найденного, не стиля.

## Этап 2. Неверные ссылки

- Импорты `src/**` и `scripts/**`: существуют ли цели.
- Ссылки в `docs/*.md`: файлы, якоря, `scripts/*`, `src/*`.
- `app.js`: `href`, `src`, `fetch('/api/...')` против `server.ts`.
- `index.html`: `src/href` и наличие файлов.
- Claude: ревью карты ссылок.

## Этап 3. Пустые строки

- Пользовательские тексты, которые могут стать `''`.
- Пустые состояния страниц: play/search/stories/admin.
- `renderPanel`, `toast`, `innerHTML`, `textContent` с пустыми значениями.
- Старые кампании с отсутствующими полями.
- Claude: ревью списка мест.

## Этап 4. Повторная проверка ссылок

- После фиксов повторить этап 2.
- Проверить, что новые ссылки не появились битыми.
- Claude: финальный diff review.

## Ограничения

- Не менять security/цензуру.
- Не удалять кампании/бэкапы.
- Не менять формат данных без миграции.
- Каждый фикс — отдельный коммит после approval.
