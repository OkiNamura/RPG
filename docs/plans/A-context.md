# Очередь A: деньги и контекст

Цель: убрать лишние токены и расхождения, не меняя поведение мира.
Каждый пункт — отдельный коммит и проверка. A6 разделена на A6a/A6b.

## A1. `present === true` в Director и групповой сцене

Файлы: `src/server.ts`, `src/core/state.ts`.

- Director и groupScenes: `actor.present === true`, плюс `!actor.archived`.
- `updateSceneCheckpoint` (`state.ts`) собирает участников по тому же правилу,
  иначе state и промт расходятся.
- `social.ts` и `app.js` **не трогаем** в A1: там `present !== false` влияет на
  свидетелей/репутацию. Расхождение фиксируем в CONTEXT.md отдельно.

Проверки:

- NPC без флага не попадает в сцену;
- NPC с `present=true` попадает;
- пати с `undefined` не считается присутствующей;
- архивный NPC не попадает.

## A2. Один блок фракций

Файл: `src/core/context.ts`.

- Оставить одну строку `Фракции:`.
- Выводить независимо от наличия `reputation`.
- Состав фракции — только если `roster` пересекается с NPC, у которых
  `present === true`.
- Лидер/тень/состав — только для такой фракции; иначе имя, attitude, связи.

Проверка: `Фракции:` ровно один раз, в том числе без `reputation`.

## A3. Лимиты `renderState`

Файл: `src/core/context.ts`.

- NPC:
  - `present === true` — полный блок;
  - остальные — имя, роль, отношение; без `mind`, без состава;
  - отсутствующих не больше 8; порядок — как в массиве, без выдуманного
    «последнего появления».
- Квесты:
  - все `active` и `frozen` — не режем, это последствия;
  - `done/failed` — только последние 3 по порядку массива;
  - если активных больше 12, всё равно выводим все, но помечаем счётчиком.
- Скрытые факты:
  - максимум 12 свежих;
  - если есть ещё — строка `ещё N скрытых фактов`;
  - факты, связанные с текущей сценой/фракцией, не выкидывать.
- Обещания: 8 + счётчик остальных.
- События/фронты/часы оставить.

Проверки:

- секрет отсутствующего NPC не попадает в state;
- 50 NPC → отсутствующие ограничены;
- 15 активных квестов → все активные на месте;
- `frozen` не пропадает.

## A4. Один вызов ведущего при повторе действия

Файл: `src/core/turn.ts`.

- `actionRepeat > 0.72` добавляет директиву до генерации.
- Повторный вызов — **только** `proseSimilarity(previous, new) > 0.82`.
- `stalled` остаётся для сцены, но не вызывает модель.
- Стоимость и `tokensOut` повторного вызова добавлять в `totals`/`cost`
  (сейчас учитывается только первый ответ).

Проверки:

- повтор действия + новый ответ → 1 вызов;
- повтор ответа → 2 вызова;
- повторный вызов учитывается в деньгах.

## A5. Единый pipeline хода

Файлы: `src/core/storage.ts`, `src/server.ts`, `src/web/app.js`.

Проблема: regenerate/edit не могут восстановить `timeTarget`, фокус и кубик,
их нет в снимке; подготовка скопирована в 4 местах.

Решение:

- В `TurnSnapshot` добавить необязательное:

```ts
turnOptions?: {
  dice?: boolean;
  focus?: string[];
  timeTarget?: TimeTarget | null;
};
```

- При записи снимка сохранять реальные опции хода.
- Старые снимки без `turnOptions`: `dice=false`, `focus=[]`, `timeTarget=null`.
- Regenerate использует **те же** опции, что исходный ход: тот же кубик, фокус,
  цель времени. Это воспроизводимость, а не новый бросок.
- Edit берёт из снимка только кубик и фокус; цель времени заново выводится из нового текста (старую не наследуем).
- `timeClarification` не входит в общий `prepareTurn` для regenerate/edit:
  клиент edit не умеет обрабатывать `{clarification}`.
- `variantFrom` сохраняется в общем `finishTurn`.

Проверки:

- ход с `timeTarget:{kind:'event'}` → рестарт сервера → regenerate: цель времени
  та же;
- regenerate старого снимка (без `turnOptions`) не падает;
- edit сохраняет фокус;
- варианты ответа не ломаются.

## A6a. Порядок lore

Файлы: `src/core/context.ts`, `src/server.ts`, `docs/CONTEXT.md`.

Новый порядок:

```text
static
→ memory
→ conspect.frozen
→ history
→ conspect summary
→ lore.top
→ lore.history
→ lore.after
→ state
→ lore.depth
→ notes
→ turn
```

- `lore.top/history/after` остаются разными блоками, но стоят после истории,
  чтобы динамический лор не сжигал префикс.
- Обновить шапку `context.ts` и раздел «Контекст» в `CONTEXT.md`.
- Не менять `session.summary` и `trimSummary` в этом пункте.

Проверка: при смене набора лора префикс до истории включительно стабилен;
старые кампании открываются.

## A6b. Бюджет контекста

Файлы: `src/core/context.ts`, `src/server.ts`.

- Бюджет применяется **только при сборке контекста**, не при записи.
- `session.summary` и `trimSummary(65000)` не трогаем: данные не удаляются.
- В контексте summary режется до 24 тыс. символов; вытесненное остаётся в
  `arcArchive`.
- История не сокращается с 48 до 24 без отдельного решения пользователя.
- Сейчас A6b режет только summary в контексте и флагирует превышение.
- Жёсткое вытеснение `lore.depth`/`lore.after`/`notes` не делаем: `notes`
  содержит смерть, якорь сцены и директивы режиссёра.
- Жёсткий лимит 25 тыс. токенов только отображается в Context Inspector,
  без удаления `notes` и истории.
- Включить счётчики в inspector: summary до/после, history, lore, state.

Проверки:

- старая кампания 504 хода: `summary + arcArchive` не уменьшаются после 10 ходов;
- контекст не превышает лимит;
- inspector показывает выкинутое;
- нет регрессии времени/сцены.
