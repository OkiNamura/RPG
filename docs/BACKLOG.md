# Бэклог Omika

Обновлено: 2026-11-06. Здесь выбранное на ближайшую работу и отложенные задачи с описанием.

## Ночной результат

Сделано в разной степени готовности:

- **B1 Context Inspector** — экран сегментов, токенов и активации лора; снимок сохраняется в `data/inspectors` и переживает перезапуск.
- **B2 World Info** — constant/selective/вторичные ключи/порядок/позиция/бюджет/sticky/cooldown/лог активации.
- **B3 Ветки** — сохранение текущего состояния, список, загрузка, удаление; full state. Добавлена отмена последнего хода.
- **B7 Group scenes** — групповой блок в промте и выбор фокуса сцены; несколько NPC получают разные реакции.
- **B8 NPC minds** — goals/secrets/knows/notKnows/plans/mood в карточке и контексте.
- **B9 Vector memory** — локальный hashing-векторный индекс прошлых сцен с cosine-retrieval; внешние embeddings опционально.
- **B10 Story Director** — отдельный агент `director` с короткими директивами перед ходом.
- **B16 Image queue** — серверная последовательная очередь, статус и отмена через `/api/images/cancel`.
- **B17 Image profiles** — natural/danbooru, negative, референсы, model-aware Qwen; при первом кадре без мастер-листа герой получает автоматический референс.
- **B20 Anti-slop** — удаление буквальных повторов и части типовых фраз.
- **B24 Economy** — формула цены по типу вещи, месту и валюте; рынок с покупкой/продажей, цена в нужной деноминации (медь/серебро/рубли/кредиты).

Всё это включается/выключается в **Админка → Функции**.

## Общие принципы

- всё новое не должно ломать старые кампании;
- данные пользователя не удаляем, перед миграциями — бэкап;
- механика считается на сервере, модель только предлагает;
- новые агенты не должны удваивать стоимость каждого хода без явного включения;
- фича по умолчанию выключена, если она меняет стиль игры.

## Следующие шаги после фазы 1–2

Приоритет сверху вниз.

### 1. Поиск по трассам через общий API

- `/api/search?q=` должен искать не только лог, но и `traces.db`.
- Отдельная группа результатов «Трейсы» с кампанией, ходом, моделью и сниппетом.
- Принимать `scope=all|log|traces`.
- Индекс трасс пересобирать по кнопке/команде, не на каждый запрос.

### 2. Поиск по конспекту, сводкам и карточкам

- FTS/таблицы для `summary`, `arcArchive`, `cards`, `factions`.
- Ищем не только точные слова, но и участников/локации из сводки.
- В результатах — «конспект», «карточка», «локация», «фракция».

### 3. Переход к конкретному ходу из поиска

- Клик по логу открывает историю и прокручивает к нужному ходу.
- Подсветка найденного фрагмента.
- Для карточек/локаций — сразу открывать соответствующую карточку.
- Не менять состояние кампании при переходе.

### 4. Инкрементальная запись снимков

- Сейчас при новом ходе перезаписываются все 24 снимка кампании.
- Писать только новый/изменённый снимок через upsert.
- Удалять только вытесненные ходы.
- Замерить write latency до/после.

### 5. Автобэкап БД

- Периодический `VACUUM INTO` для `snapshots.db` (критичная БД), `search.db`, `traces.db`.
- Ротация: хранить N последних копий.
- Бэкап перед миграцией схемы.
- Проверить восстановление из копии на тестовой кампании.
- Не бэкапить во время активной записи без WAL/checkpoint.

### 6. Инкрементальная синхронизация поиска

- Сейчас `syncCampaignIndex` переписывает все строки кампании после каждого `persist`.
- Обновлять только изменившихся акторов/локации/предметы и новые строки лога.
- Полная пересборка — команда восстановления, не обычный путь.

### 7. Целостность и fallback снимков

- Проверка `PRAGMA integrity_check` при старте.
- Если `snapshots.db` битая: не терять игру, предложить восстановление из `data/backups`.
- Держать последнюю JSON-копию снимков при миграции.

### 8. Фаза 3: полная БД

- Только при нескольких пользователях/кампаниях или реальной конкуренции за запись.
- Нормализовать state, миграции схемы, конкурентный доступ.
- Сейчас не делать: JSON остаётся источником истины.

На один ход:

```text

~0,004 $ за ход
~0,40 $ за 100 ходов
```

Причины:

- `summary` — 64 504 символа при лимите `trimSummary = 65 000`;
- `renderState` — 36 309 символов (13 NPC, 31 локация, 10 квестов, лор);
- окно истории — 33 781 символ (48 сообщений);
- итого ~135 тыс. символов контекста на ход;
- кэш покрывает только 9 млн из 39,5 млн входных токенов.
