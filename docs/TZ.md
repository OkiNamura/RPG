# Техническое задание: Omika Engine 

Версия: 1.0  
Назначение: переносимый движок текстовой ролевой игры.  
Документ не содержит описаний персонажей, сюжетных планов, роадмапа и контента конкретных кампаний.

---

## 1. Назначение

Система принимает действие игрока, формирует контекст сцены, получает ответ ведущей модели, детерминированно применяет изменения состояния, сохраняет историю и отображает результат в браузере.

Основные свойства:

- текстовая RPG с ведущей моделью;
- состояние — типизированный JSON, а не проза;
- сервер — единственный источник истины;
- модель предлагает изменения, сервер их валидирует;
- контент мира создаётся при старте кампании и дальше не переписывается;
- приложение работает как PWA;
- старые кампании должны открываться после обновления.

---

## 2. Термины

| Термин | Значение |
|---|---|
| Кампания | Одна игра: мир, состояние, история, настройки. |
| Ход | Один цикл «ввод игрока → ответ ведущего → изменение состояния». |
| Состояние | Типизированный JSON с фактами мира и героя. |
| Дельта | Набор изменений состояния, предложенный моделью. |
| Сцена | Ограниченный отрезок повествования: место, участники, цель. |
| Конспект | Сжатая память о прошлых ходах. |
| Снапшот | Полная копия состояния на конкретном ходу. |
| Норма | Ценность мира с весом; используется для реакции faction/окружения. |
| Фронт | Долгий процесс мира, который двигается между ходами. |
| Часы | Видимый прогресс фронта или квеста. |
| Артефакт | Сохранённый файл изображения или карточки. |

---

## 3. Архитектура

### 3.1. Компоненты

```text
Браузер
  ├─ SPA: hash-роутер, экран игры, админка
  ├─ SSE-клиент: поток текста ведущего
  └─ PWA: service worker, кэш оболочки

Сервер
  ├─ HTTP API
  ├─ SSE-поток
  ├─ оркестратор хода
  ├─ контекст и агенты
  ├─ детерминированный слой состояния
  ├─ поиск и снапшоты
  └─ очередь изображений

Хранилище
  ├─ JSON кампаний — источник истины
  ├─ SQLite: поиск, снапшоты, трассы
  └─ Файлы: изображения, карточки, бэкапы
```

### 3.2. Технологические требования

- Node.js ≥ 22.6;
- нативный TypeScript/ESM;
- нулевые runtime-зависимости;
- SQLite через встроенный `node:sqlite`;
- сервер слушает `127.0.0.1`;
- статика и API отдаются одним процессом;
- конфигурация — через `.env`, секреты не попадают в браузер.

### 3.3. Поток хода

```text
1. Валидация ввода
2. Сборка контекста
3. Вызов ведущей модели (stream)
4. Разбор прозы и дельты
5. Проверка повторов
6. Применение дельты
7. Агент состояния
8. Цель времени
9. Обновление сцены
10. Тик мира
11. Снапшот
12. Индексация поиска
13. Сохранение
14. Ответ клиенту
```

Порядок этапов 6–10 фиксирован. Цель времени применяется после агента состояния, чтобы модель не переписала выбор игрока.

## 4. Функциональные требования

### 4.1. Аутентификация

- Вход по паролю.
- Капча на форме входа.
- Сессия в HttpOnly cookie.
- Все игровые и админские API требуют авторизации.
- Выход очищает сессию.
- Админка недоступна без роли администратора.

### 4.2. Кампании

- Создание кампании с настройками мира, тона, сложности и пожеланий.
- Генерация неизменяемой библии кампании:
  - мир;
  - тон;
  - герой;
  - визуальный стиль;
  - сюжетная рамка мира.
- Список кампаний, продолжение, удаление, заморозка.
- Импорт/экспорт кампании.
- Старые кампании нормализуются при загрузке без потери данных.
- Удаление кампании — только в корзину с возможностью восстановления.

### 4.3. Игровой экран

- Лента сообщений с ленивой загрузкой: последние 50, далее по 50.
- Потоковый вывод ответа ведущего.
- Поле ввода: отправка, отмена, повтор, очередь незавершённого хода.
- Панель состояния:
  - время;
  - место;
  - сцена;
  - здоровье;
  - эффекты;
  - репутация;
  - фракции;
  - фронты;
  - часы;
  - задачи;
  - события.
- Меню игры: события, связи, история, ветки, отмена хода, иллюстрации.
- Кликабельные изображения с метаданными.
- Клавиатурные сокращения и доступное управление.

### 4.4. Контекст

Контекст собирается слоями в фиксированном порядке:

```text
1. Статика: ядро, мир, герой
2. Память истории: legacy, pinned, learned
3. Замороженный конспект
4. История последних ходов
5. Конспект прошлого
6. Лор: top, history, after
7. Память по сцене (recall)
8. Состояние
9. Лор глубины
10. Заметки и проверки
11. Ход игрока
```

Точные бюджеты и лимиты — в разделе 11.2.

Требования:

- динамические блоки стоят после стабильных;
- окно истории сдвигается блоками, а не по одному сообщению;
- в контекст попадают только релевантные записи лора;
- в контексте есть явный бюджет;
- при превышении бюджета сокращаются:
  - конспект;
  - окно истории;
  - второстепенные локации;
  - нерелевантный лор.

Целевой бюджет:

```text
до 20–25 тыс. входных токенов на обычный ход
```

### 4.5. Ведущая модель

- Получает контекст и возвращает прозу.
- Не управляет цифрами напрямую.
- Не задаёт вопросы «что дальше».
- Не приглашает игрока к выбору.
- Не выдумывает отсутствующих персонажей.
- Не повторяет предыдущий ответ.
- Ответ должен двигать сцену новым фактом.

### 4.6. Дельта состояния

Модель возвращает структурированные изменения:

```text
время
место
погода
здоровье
раны
предметы
деньги/валюты
отношения
репутация
нормы
события
квесты
фронты
скрытые факты
```

Требования:

- каждое изменение проверяется;
- деньги не уходят в минус;
- нельзя удалить отсутствующий предмет;
- нельзя нанести рану без описания;
- неизвестные поля отбрасываются;
- ошибка одного поля не отменяет весь ход.

### 4.7. Агент состояния

- Работает после ведущего.
- Обновляет цифры и место.
- Не переписывает прозу.
- Не переписывает цель времени игрока.
- При ошибке ход не блокируется.
- Имеет собственный таймаут.

### 4.8. Время

- Время двигается только по правилам мира.
- Явная длительность игрока приоритетна.
- Обычное действие не может скачком менять сутки.
- Запрещён откат времени назад.
- Ожидание не создаёт скрытых скачков.
- Долгое ожидание возможно только при явной цели.
- Время не привязано к жёсткому расписанию сцен.

### 4.9. Сцена

Состояние сцены:

```text
id
startedTurn
updatedTurn
place
participants
goal
lastBeat
stalls
question
closedTurn
closeReason
```

Требования:

- сцена обновляется после хода;
- при смене места начинается новая сцена;
- участники — только явно присутствующие (`present === true`);
- повтор действия игрока увеличивает `stalls`;
- при `stalls === 2` Director вызывается, при `stalls >= 3` сцена закрывается;
- закрытые сцены — в `sceneHistory`, до 5;
- вопрос сцены берётся только из Director;
- сцена не имеет жёсткого таймера.

### 4.10. Защита от повторов

Проверяются:

- совпадение нового ответа с предыдущим;
- совпадение действия игрока с последними действиями;
- повторяющиеся вопросы;
- повторяющиеся выходы/входы в локацию.

При срабатывании:

1. добавляется директива «сцена топчется»;
2. выполняется один повторный запрос;
3. при неудаче ход помечается проблемой `повтор сцены`.

Порог совпадения ответа: 0.82.  
Порог совпадения действия: 0.72.

### 4.11. Конспект

- Append-only.
- Закрытые арки не перегенерируются.
- Старые арки уходят в архив.
- Конспект имеет жёсткий лимит.
- Лимит по умолчанию: 20–24 тыс. символов.
- При превышении старые арки не удаляются безвозвратно, а архивируются.
- Конспект не дублирует состояние.

### 4.12. Поиск и снапшоты

- Полнотекстовый поиск по:
  - логу;
  - трассам;
  - конспекту;
  - карточкам;
  - фракциям;
  - локациям.
- Переход к конкретному ходу.
- Снапшот на каждый ход.
- Откат на предыдущий ход.
- Ветки и чекпоинты.
- Восстановление после повреждения БД из бэкапа.

### 4.13. События

- Событие содержит:
  - id;
  - время;
  - название;
  - важность;
  - место;
  - признак пробуждения;
  - статус.
- События создаются из сцен, дедлайнов и шаблонов.
- Событие может прервать длинный переход.
- Просроченное событие не блокирует игру.
- События отображаются в панели и диалоге.
- События можно добавлять и удалять вручную.

### 4.14. Нормы и репутация

- Нормы мира — данные, а не код.
- Норма содержит id, подпись, вес, признак внутренней нормы.
- У фракции могут быть собственные веса.
- Один поступок может иметь разные последствия для разных фракций.
- Репутация хранится:
  - общая;
  - по фракциям.
- Последствия нарушения:
  - публичная репутация;
  - отношение свидетелей;
  - мораль;
  - статус-дебафф.
- Без свидетелей публичный дебафф не ставится.
- Скрытое нарушение фиксируется как скрытый факт.

### 4.15. Мир между ходами

- Фронты создаются из фракций мира.
- Фронт имеет:
  - цель;
  - прогресс;
  - статус;
  - связанный квест;
  - флаг события NPC.
- Фронты двигаются детерминированно.
- На скорость влияют:
  - отношение фракции;
  - публичная репутация;
  - события.
- При 25% создаётся квест.
- При 50% создаётся событие линии NPC.
- При 100% фронт завершается.
- Квест имеет часы и может провалиться.
- Отношения фракций строятся по совпадению норм.
- Союзы и войны фиксируются как состояние, а не как текст.

### 4.16. Изображения

- Режимы: сцена, портрет, карточка, лист, предмет, локация, герой.
- Промт сцены собирается из контракта:
  - место;
  - время;
  - погода;
  - герой;
  - присутствующие;
  - действие;
  - запрещённые персонажи;
  - референсы.
- В кадр попадают только участники с `present === true`.
- Посторонние люди запрещены.
- Жанр мира имеет приоритет над стилевым дефолтом.
- Для современного мира запрещены фэнтези-элементы.
- Действие игрока входит в промт раньше прозы.
- Identity-seed персонажа стабилен и не зависит от хода.
- Референсы лица берутся из мастер-листа или портрета.
- Асинхронная очередь:
  - один кадр за раз;
  - прогресс;
  - отмена;
  - повтор;
  - отображение последнего времени кадра.
- Ошибка генерации не должна ломать ход.

### 4.17. Интерфейс

- Мобильная и десктопная раскладка.
- Отсутствие горизонтального скролла.
- Модалки:
  - закрытие по кнопке;
  - закрытие по фону;
  - Esc;
  - свайп вниз;
  - системная кнопка «Назад».
- Фокус-трап внутри модалки.
- Возврат фокуса на кнопку открытия.
- Свайп вправо — назад на списках.
- Pull-to-refresh — только на списках, не в игре, не в формах.
- Кэш экрана и индикатор загрузки.
- Доступность: контраст, подписи, клавиатура.

### 4.18. Админка

- Список всех кампаний.
- Статистика.
- Управление ключами.
- Управление ядром и агентами.
- Управление функциями.
- Обращения:
  - статус;
  - короткий отчёт;
  - доработка;
  - текст ответа.
- Ограничение редактирования карточек для игроков.

## 7. Нефункциональные требования

### 7.1. Производительность

- Первый экран игры: кэш + индикатор загрузки.
- История: 50 сообщений, далее по 50.
- Сборка контекста: без полного чтения всех файлов на каждый ход.
- Снапшоты: инкрементальная запись.
- Поиск: инкрементальная индексация.

### 7.2. Стоимость

Бюджет обычного хода:

```text
до 20–25 тыс. входных токенов
```

Лимиты:

- конспект: 20–24 тыс. символов;
- окно истории: 24 сообщения;
- состояние: только активная сцена и важные сущности;
- лор: только релевантный;
- директор: не каждый ход.

### 7.3. Надёжность

- Таймаут модели: 120 секунд.
- Один повтор при обрыве.
- Ход не теряется при обрыве ответа.
- Пустой ответ заменяется безопасной заглушкой.
- Ошибка изображения не блокирует ход.
- Бэкапы снапшотов и поиска.
- Проверка целостности БД при старте.

### 7.4. Безопасность

- Пароль и секреты только на сервере.
- HttpOnly cookie.
- Проверка id кампании и имён файлов.
- Запрет path traversal.
- Ограничение размера ввода.
- Админские маршруты защищены.
- Публичный запуск только после пентеста.

### 7.5. Совместимость

- Старые JSON нормализуются.
- Новые поля необязательны.
- Миграции не удаляют данные.
- Перед миграцией — бэкап.
- UI не должен зависеть от наличия новых полей.

### 7.6. Доступность

- Контраст не ниже WCAG AA для текста.
- Подписи у полей.
- Escape и Tab.
- Фокус-трап.
- `prefers-reduced-motion`.
- Отсутствие горизонтального скролла на 390 и 1440 px.

## 9. Критерии приёмки

- Сервер запускается одной командой.
- Новая кампания создаётся без ручных файлов.
- Ход проходит end-to-end.
- Состояние сохраняется и восстанавливается.
- Время не откатывается.
- Сцена не зацикливается.
- В кадр не попадают отсутствующие.
- Портрет сохраняет identity-seed.
- Поиск находит ход и открывает его.
- Мобильная и десктопная вёрстка без горизонтального скролла.
- Модалки закрываются кнопкой, фоном, Esc, свайпом и системным «Назад».
- Pull-to-refresh не мешает скроллу в игре.
- Старые кампании открываются.
- Все обязательные тесты зелёные.
- Секреты не попадают в клиент.
- Есть бэкап перед миграцией.

## 11. Фактическая реализация (аудит 2026-11-07)

Раздел фиксирует то, что реально работает в коде, а не только целевые требования.

### 11.1. Порядок хода

```text
prepareTurn:
  groupFocus
  pickLore
  pickNotes (кубик)
  augmentFeatureNotes (векторная память, Director, групповая сцена)
  timeTargetNote
  numericSnapshot

runTurn:
  buildContext
  ведущая модель
  пустой ответ → 1 повтор
  повтор ответа >0.82 → 1 повтор
  delta → critic → лог

afterTurn:
  repair
  state agent + summary (раз в 3 хода)
  social → revive
  timeTarget → scene → world tick
  time guard → promises → snapshot → trace → vectors → persist
```

### 11.2. Контекст

Фактический порядок:

```text
static
→ memory (legacy)
→ memory.pinned
→ memory.learned
→ conspect.frozen
→ history
→ conspect summary
→ lore.top
→ lore.history
→ lore.after
→ memory.recall
→ state
→ lore.depth
→ notes
→ turn
```

Лимиты:

- summary в контексте: 24 000 символов; полный summary не меняется;
- общий бюджет: 25 000 токенов, только флаг `over`;
- история: 24 хода (48 сообщений), сдвиг блоком 20;
- pinned: 8 записей / 4 000 символов;
- recall: 6 / 3 000;
- legacy memory: 4 000;
- общий бюджет памяти: 9 000 символов;
- learned: 2 незакреплённые записи важности 3, до 300 символов;
- лор: 8 записей / 6 000 символов;
- state compact: отсутствующие NPC без mind (8), active/frozen квесты + 3 закрытых, факты 12 + счётчик, обещания 8 + счётчик; агент состояния получает полный state.

Кэш: динамические блоки после истории; `memory.learned` не зависит от recall.

### 11.3. Память

`MemoryEntry`:

```text
id, kind: fact|journal, text, keys[], importance 1..3,
pinned, createdTurn, source: player
```

- хранится в сессии/кампании, не в `GameState`;
- переживает undo/regenerate; ветки делят память; restart очищает;
- API: `POST /api/campaign/:id/memory-entry` — add/update/delete/pin/unpin;
- лимиты API: text ≤ 500, keys ≤ 8, записей ≤ 50; 9-й pin → 400;
- recall по ключам через `hitsKey` (подстрока + грубый стемминг);
- `learned` — 2 самые старые незакреплённые journal-записи важности 3, не дублируют recall/pinned.

### 11.4. Сцена и Director

`SceneState`: id, startedTurn, updatedTurn, place, participants, goal, lastBeat, stalls, question, closedTurn, closeReason.
`sceneHistory` — до 5 записей.

- сцена закрывается сменой места или 3 топтаниями подряд;
- новая сцена — на следующем ходе; question только из Director (первая строка с `?`, ≤160);
- Director вызывается при новой сцене, `stalls === 2`, откате/regenerate, либо раз в 3 хода;
- иначе — шаблонная заметка;
- Director не вызывается на каждом ходе.

### 11.5. Мир

- фронты: прогресс +1..3 за тик от времени/репутации/вражды;
- часы: + тот же pressure, при заполнении `done`;
- события: по времени, повышают фронт;
- отношение фракций:
  - при наличии фронтов: +1 если разница отношения к герою 1..20; −1 если разрыв фронтов ≥20;
  - clamp ±100;
  - война при ≤−30, выход при ≥−25; союз при ≥30, выход при ≤25;
  - обе стороны отношения синхронны.
- рынок: цена = базовая × множитель места × вариация 0.90..1.10 × курс; репутация только в `/market`: ≥40 → 0.9, ≤−40 → 1.35;
- отношения в state: до 4 значимых связей на фракцию + счётчик.

### 11.6. Эпоха и альтернативное летоисчисление

- шкала года: от −10 000 до 999 999 999, центр 2000;
- `epochYear` и `eraLabel` — независимые параметры;
- галочка «своё летоисчисление» только показывает поле эпохи;
- шкала года, ручной ввод и подсказка остаются видимыми;
- в промт уходят оба параметра: относительная эпоха и альтернативное название.

### 11.7. Кубик, экономика, ранги

- d36: 1 — критический провал, 36 — джокер бездны; джокеры 34/35/36 с бонусами +10/0/−10;
- итог = грань + навык + бонус джокера; сложность задаётся сценой;
- экономика: базовая цена × множитель места (дворец 2.4, город 1.5, деревня 0.8, дорога 1.1, таверна 1.2, тюрьма 0.9) × валюта;
- ранги: 21 ступень, старт FFF/FF/F, повышение по rankPoints, locked не повышается.

### 11.8. Изображения

- кадр только при `present === true`;

- референсы героя/карточки;
- очередь, отмена, стоимость, fallback.
