# Pairing: DeepSeek + Claude

Короткий протокол для парной работы.  
Не регламент на каждый чих: документ нужен только для задач крупнее мелкого фикса.

## Роли

- **DeepSeek** — руки: пишет код, запускает сервер, тесты, смотрит реальные файлы и состояние. Единственный, кто пишет в репозиторий.
- **Claude** — глаза: читает диффы, коммиты, ТЗ и контекст, ищет риски, противоречия и пропущенные edge cases. В репозиторий не пишет.
- **Пользователь** — владелец продукта: ставит задачу, выбирает приоритет, может отменить любое решение.

## Арбитраж

- Не решает тот, кто последний закоммитил.
- При техническом споре DeepSeek отвечает за проверяемый результат: он видит код и может запустить тест.
- Claude может не согласиться, но аргумент должен быть проверяемым: файл, строка, тест, сценарий.
- Продуктовое решение и приоритет — за пользователем.
- Если спор не решается фактами, фиксируем оба варианта и не делаем вид, что один «правильный».

## Обязательные правила

1. Claude не пишет в репозиторий.
2. DeepSeek присылает не пересказ, а:
   - diff;
   - commit hash;
   - команды проверки;
   - фактические результаты.
3. Для крупной задачи обязательно поле **«что НЕ проверено»**.
4. Не передавать секреты, `.env`, токены и персональные данные.
5. Один активный владелец изменений. Параллельно можно только читать/исследовать.
6. После изменений — тесты, `tsc`, UI/a11y, если затронут интерфейс.
7. Мелкие фиксы (опечатка, одна кнопка, один CSS-фикс) идут без записи в этом файле.

## Шаблон крупной задачи

По 4–5 строк, не больше:

```text
Задача:
Владелец изменений:
Файлы:
Критерии приёмки:
Что НЕ проверено:
Diff / commit:
```

## Первый пакет

```text
Задача:
  Архитектурное ревью: память, бюджет контекста, сцена, стоимость хода.

Владелец изменений:
  DeepSeek. Claude — read-only ревью.

Файлы:
  docs/CONTEXT.md
  docs/TZ.md
  docs/COMPETITIVE-RESEARCH.md
  src/core/context.ts
  src/core/turn.ts
  src/core/state.ts
  src/server.ts

Критерии приёмки:
  Claude находит противоречия и риски, DeepSeek отвечает планом/диффом,
  после чего фиксируется решение по памяти и бюджету.

Что НЕ проверено:
  Реальный расход токенов после введения бюджета.
  Поведение на старых кампаниях после смены памяти.
  Нужна ли карта в активном UI — код и решение расходятся.

Diff / commit:
  см. коммит с docs/PAIRING.md и docs/CONTEXT.md
```

## Что смотреть первым

1. Где сейчас противоречат друг другу `TZ.md`, `CONTEXT.md` и код.
2. Какая память нужна: единый конспект, три уровня или гибрид.
3. Как закрывать сцену без жёстких таймеров.
4. Что вырезать из контекста, чтобы не потерять качество.
5. Какие пункты ТЗ не влезают в текущую архитектуру.

## Формат ответа Claude

Лучше так:

```text
Блокер:
  файл:строка / сценарий
  почему это ломает архитектуру
  что проверить

Риск:
  ...

Не согласен:
  ...

Что не проверено:
  ...
```

Без общих слов «нужно улучшить». Нужны конкретные места и проверяемые сценарии.

## Автоцикл (DeepSeek ведёт, Claude проверяет)

Пользователь пишет задачу только DeepSeek. Дальше DeepSeek сам проходит цикл и зовёт Claude командой:

```text
node scripts/claude-review.mjs plan "<задача>" "<план или путь к файлу с планом>"
node scripts/claude-review.mjs diff "<задача>" [база, по умолчанию HEAD~1]
```

Код выхода: `0` — ОК, `2` — НЕ ОК (есть блокер), `1` — Claude не запустился.
Каждое ревью сохраняется в `docs/reviews/`.

Цикл для задачи крупнее мелкого фикса:

1. **План.** DeepSeek пишет план: файлы, подход, что не трогаем, какие тесты.
2. **Ревью плана.** `claude-review.mjs plan`. НЕ ОК → правит план (макс. 2 круга).
3. **Код + дебаг.** DeepSeek пишет, гоняет `typecheck`, `test` и профильные тесты до зелёного. Коммитит.
4. **Ревью диффа.** `claude-review.mjs diff` с базой до начала задачи.
5. **Правки.** НЕ ОК → DeepSeek чинит блокеры, снова шаг 4. Максимум 3 круга.
6. **Итог пользователю:** коммиты, что сделано, вердикт Claude, что не проверено.

Жёсткие правила автоцикла:

- Шаги 2 и 4 не пропускаются. Мелкий фикс — только шаг 4 (или без ревью, если это опечатка/CSS).
- DeepSeek не пересказывает дифф Claude — Claude смотрит git сам.
- Блокер Claude нельзя закрыть словами «считаю нормальным»: либо исправить, либо вынести пользователю как спор.
- Не сошлись за 3 круга → стоп, оба мнения пользователю.
- Если `claude-review.mjs` вернул `1` (Claude недоступен/лимит) — не продолжать молча: сообщить пользователю, что ревью не было.
- Необратимое (миграции кампаний, удаление данных, деплой) — только после «да» пользователя.
