# ТЗ: Omika — текстовая RPG в браузере

Документ описывает всё, что есть в проекте: блоки, агентов, теги, правила,
механики, интерфейс, API и ограничения. Версия — по состоянию сборки.

---


## 1.1. Доступ

- Вход по одному паролю `OMIKA_PASSWORD`; без пароля авторизация выключена
  (локальная разработка).
- `/login`: Cloudflare Turnstile, при недоступности — арифметическая капча.
- Не более 10 неудачных попыток за 15 минут с IP; успешный вход сбрасывает счётчик.
- Сессия — HttpOnly-cookie на 30 дней, `SameSite=Lax`, `Secure` на HTTPS.
- `/api/auth`, `/login`, `/api/login`, `/api/logout` публичны; остальные
  страницы и API требуют сессию, API отвечает `401` JSON.
- Telegram-бот для фидбека (ops, не часть игры): только числовой ID владельца,
  приватный чат, 20 сообщений в час, без исполнения команд.

## 1. Что это

Локальная текстовая RPG: игрок ведёт героя, ведущий-модель пишет сцену,
агент состояния обновляет цифры, конспектировщик дописывает хронику по аркам,
иллюстраторы рисуют кадры. Всё работает через OpenRouter API или совместимый
провайдер, данные лежат файлами в `data/`, сервер — нативный Node без
зависимостей.

Запуск: `node src/server.ts` → `http://127.0.0.1:7801`.

## 2. Четыре блока истории

1. **ЯДРО** — `data/source/core.md` (~112 тыс. знаков). Правила мира и
   повествования. **Не изменяется**: сервер отклоняет правку (403), в
   интерфейсе поле только для чтения. Одно на все игры, в файл кампании не
   копируется, подставляется при загрузке.
2. **ТОН** — **промт для промта**: `data/source/tone-prompt.md`. По нему
   мастер собирает тон конкретной игры. Редактируется во вкладке «Ядро».
3. **МИР** — **промт для промта**: `data/source/world-prompt.md`. По нему
   собирается мир игры. Редактируется во вкладке «Ядро».
4. **ГЕРОЙ** — `data/source/hero-prompt.md` + форма игрока; `POST
   /api/generate/hero` собирает блок агентом.

Тон, мир и герой для каждой игры генерируются отдельно и хранятся в
кампании. Старые шаблоны тона и мира сохранены как `*.prev.md`.

Все четыре блока склеиваются в стабильный блок контекста и стоят первыми —
на этом держится кэш провайдера.

## 3. Агенты

| Агент | Роль | По умолчанию |
|---|---|---|
| `gm` | ведущий: пишет сцену | включён |
| `prompter` | мастер промтов: тон, мир, герой, теги, промты игры | включён |
| `state` | состояние: предметы, квесты, NPC, фракции, лор, время | включён |
| `summarizer` | хроника по аркам | включён |
| `artistHero` | мастер-лист героя | включается в игре |
| `artistNpc` | карточка персонажа | включается в игре |
| `artistItem` | карточка предмета | включается в игре |
| `artistScene` | кадр сцены | включается в игре |

- У каждого: модель, температура, лимит токенов, промт, включение, кнопка
  «Тест», выбор ключа API.
- Глобальные настройки — шаблон. **При создании игры создаются свои ведущий
  и иллюстратор истории**: мастер промтов собирает `gmPrompt`, температуру
  и стилевые промты художников, они сохраняются в `agents` и `meta.prompts`
  кампании. Остальные агенты берутся из базы.
- Схема агентов — версия 13. При миграции обновляются промт конспектировщика
  и лимит токенов.
- Хранятся в `data/agents.json`.

## 4. Теги

### 4.1. Каталог

**239 тегов, 3 группы.** Собирается `node scripts/build-catalog.mjs`.

| Группа | Тегов | Подгруппы |
|---|---:|---|
| Жанры и стиль | 149 | Жанры и поджанры (55), Эмоции и тон (28), Демография (6), Литературные направления (12), Формы повествования (16), Миры и сеттинги (32) |
| Контент-теги (18+ и зрелый контент) | 74 | Тёмное (24), Психология и зависимости (10), Зрелые и социальные темы (29), Специфические триггеры (11) |
| Тип повествования | 16 | Роль ИИ (3), Темп (3), Стиль речи (3), Безопасность и границы (4), Мета-команды (3) |

- У каждого тега есть **всплывающая подсказка** с коротким смыслом.
- Каталог жанров — авторский файл `data/genre-catalog.json`; контент —
  `data/content-catalog.json`; тип повествования — `data/narrative-catalog.json`.
  При сборке эти группы заменяются целиком, старые имена попадают в
  `data/removed-tags.json` для аудита.
- Эпоха задаётся не тегами, а бегунком (см. 4.3).

### 4.2. Как выбираются

Каждый тег — кнопка с тремя состояниями: пусто → **выбрать** (✓) →
**исключить** (✕) → пусто. Внизу сводка выбранного и исключённого.
У каждой подгруппы кнопки «все», «исключить», «сброс».

- **Поиска по тегам нет** — вместо него поле фразы.
- **Поле фразы**: «Опиши игру: романтическая комедия, жёсткое фэнтези…».
- **«Подобрать»** — агент-мастер получает фразу, уровень и весь список тегов,
  возвращает все подходящие (до 400, клиент просит 150). Примеры:
  «романтическая комедия» → романтика, комедия, эмоции, сёдзё, повседневность;
  «максимально жёсткое фэнтези» → тёмное фэнтези, пытки, казни, геноцид,
  инквизиция, ПТСР, абьюз, мрачное, ангст.
- **Кубик 🎲 у поля** — случайная выборка из того, что агент считает
  подходящим (45/60/75 по уровню); пустая фраза — случайные по уровню.
- **Кубик 🎲 у уровня** — локальный подбор набора под уровень (см. 5).
- Стоимость подбора фразы ~$0,0003–0,0008, время 1–3 с.
- **Локальная страховка**: до ответа модели сервер сам ищет теги по названию.
  «фэнтези» находит «Фэнтези», «Тёмное фэнтези», «Высокое фэнтези» и т.д.;
  «боевик» — «Боевик / Экшен», «Полицейский боевик». Если модель вернула
  пусто, эти совпадения остаются.

### 4.2.1. Пресеты новой игры и мир

- **Пресет** — `data/presets/game_000000001_name.json`, одно место хранения
  настроек старта: название, уровень, эпоха, пол, смерть, выбранные теги,
  мир, герой, навыки, режим опыта.
- На шаге 1 — блок **«Мои пресеты»**: загрузить/удалить.
- На шаге 3 — кнопка **«Сохранить пресет»**: сохраняет заполненное, не создаёт
  игру. Повторное сохранение обновляет пресет.
- **Мир** — отдельный блок: свободное описание + сгенерированный текст
  (редактируется). Генерация учитывает и теги, и описание; результат
  сохраняется в пресете и в тексте кампании.
- API: `GET/POST /api/presets`, `DELETE /api/presets/:id`.

### 4.3. Эпоха

- Бегунок от −10 000 до +999 999 999, центр шкалы — 2000-е.
- Влево прошлое линейно, вправо будущее по логарифмической шкале.
- Рядом поле ручного ввода года (до 9 знаков), синхронизировано с бегунком.
- Значение уходит в генерацию тона строкой `Эпоха: …` и в мету кампании
  (`epochYear`).
- **«Своё летоисчисление»** — галочка для миров без обычного года: бегунок
  скрывается, вместо него поле «Третий век Пепла, 12-й год после Разлома».
  Метка уходит в мир и в правила (`altTime`, `eraLabel`).

## 5. Уровень повествования (0–11)

Ползунок в «Новой игре», рядом кубик подбора тегов. Значение хранится в мете
кампании (`toneLevel`) и директивой уходит в блок тона.

| Уровень | Название |
|---:|---|
| 0 | Сказка для детей |
| 1 | Уютное фэнтези |
| 2 | Доброе приключение |
| 3 | Классическое фэнтези |
| 4 | Мрачное фэнтези |
| 5 | Тёмное фэнтези |
| 6 | Жёсткое тёмное фэнтези |
| 7 | Жестокость и кровь |
| 8 | Убийства и расчленение |
| 9 | Жертвоприношения и культы |
| 10 | За гранью |
| 11 | Максимум без смягчений |

- Кубик у уровня: 22 / 28 / 34 / 42 / 52 тега по диапазонам, тёмное
  добавляется с 5-го уровня, контент 18+ — с 5–6-го.
- **Граница:** сексуальное насилие и сексуализация несовершеннолетних не
  описываются ни на одном уровне. Встроенного контент-фильтра нет: взрослые
  NSFW-сцены модель может выдавать, если включены соответствующие теги.

## 6. Создание игры

Шаги мастера: **1) Тон и мир → 2) Герой → 3) Сборка**.

1. Название, описание мира, теги, уровень, эпоха.
2. Тон генерируется по тегам и уровню; мир — по описанию.
3. Герой: шаблоны + свои поля, генерация агентом.
   Переключатели: **пол** (мужской / женский) и **смерть**
   (постоянная / «может очнуться»). Пол уходит в блок героя и
   `meta.gender`; режим смерти — в `meta.permadeath` и в правила контекста.
4. Сборка: проверка и создание кампании.

При создании сервер сам вызывает мастера промтов и сохраняет в игру:

- фиксированный промт ведущего с отдельной секцией `# ТОН` (тон не
  переписывается) и температуру;
- промты иллюстраторов (герой, персонаж, предмет, сцена);
- `meta.prompts`, `meta.tags`, `meta.toneLevel`, `meta.epochYear`,
  `meta.gender`, `meta.permadeath`, `meta.altTime`, `meta.eraLabel`,
  `meta.xpMode`.

Создание занимает ~6–9 с (один дополнительный вызов модели), стоимость
~$0,001–0,002. Температура ведущего берётся из ползунка и не перебивается
мастером промтов: первый ход и перезапуск используют одно значение.

## 7. Ход игры

1. Контекст собирается **до** изменения состояния (чтобы кэш считался верно).
2. Ведущий пишет сцену — потоком (SSE) или обычным ответом.
3. Параллельно: агент состояния правит цифры, конспектировщик дописывает
   хронику (раз в 3 хода).
4. Ответ сохраняется со снимком хода (откат, перегенерация, варианты).
   Варианты переключаются только у последнего хода: более ранний ход вернул бы
   откат истории, поэтому сервер отвечает 409. Снимки хранят последние 24 хода
   без лога, старые чистятся при загрузке.

Слои контекста: промт ведущего (`# ВЕДУЩИЙ` + `# ТОН`) → `# ПРАВИЛА` →
`# МИР` → `# ГЕРОЙ` → настройки игры/ИИ → память → арки → история (окно
24 хода, сдвиг блоками по 20) → конспект → состояние → лор-книга → заметки →
ход игрока.

Ядро — `data/source/core.md` — не меняется игрой. Тон генерируется по
`tone-prompt.md`, вставляется в GM-промт отдельной секцией `# ТОН` дословно и
не переписывается мастером промтов. Мир идёт сразу после `# ПРАВИЛА`, герой —
следом; второго блока тона нет.

**Стартовая локация:** при создании игры не выбирается и не парсится из мира.
Состояние стартует с `place = «неизвестно»`; первый ход получает полное ядро
(генератор стартовой сцены), ведущий сам определяет место, а агент состояния
записывает его в `place`.

**Время:** если ведущий не сдвинул часы, сервер сам добавляет +1 час с
переходом через сутки. Время всегда идёт.

## 8. Механики

- **Кубик d36** (галочка 🎲 у ввода): 36 граней, 34 — джокер удачи (+10),
  35 — судьба (переброс), 36 — бездна (−10). Результат — карточкой в ленте.
- **Проверка действием**: итог = грань + половина подходящего навыка + бонус
  джокера, сложность 20. Навык выбирается по глаголу действия (крадусь →
  Скрытность, говорю → Красноречие, бью → Сила и т.д.).
- **Критический провал**: грань 1. Если навык ≤ 5 — герой может погибнуть
  (спотыкается и падает на собственное оружие, здоровье 0, флаг dead). Если
  навык выше — тяжёлая рана, но герой выживает. Игрок видит последствия,
  не цифры.
- **Генератор чисел**: `node scripts/random.mjs [грани] [сколько] [--seed текст]
  [--skill N]` — простой CLI, без seed использует crypto.randomInt, с seed —
  тот же mulberry32, что и в игре.
- **Скрытые проверки**: 8 скиллов (Сила, Ловкость, Скрытность, Воля,
  Восприятие, Красноречие, Знание, Выживание), значения 0–20.
- **Мысли героя**: строка интуиции и страхов под лентой, агент обновляет.
- **Фракции**: карточки с главой, серым кардиналом и составом, скрытые члены.
- **Квесты** со сроком в ходах: просрочка закрывает дело, пишет в архив и
  оставляет крючок.
- **Архив**: выполнено, брошено, потеряно, выброшено — не удаляется.
- **Лор-книга**: записи с ключами, в контекст попадают только совпавшие;
  автолор заводит записи о новых местах, фракциях и тварях.
- **Память истории**: закреплённые игроком факты, идут в каждый промт.
- **Отношения в пати**: агент заполняет при напряжении, ревности, тепле.
- **Крючки** дедуплицируются по смыслу и ограничены 30 штуками; вытесненные уходят в архив.
- **NPC и пати** дедуплицируются по имени без регистра и пунктуации; один персонаж не может быть одновременно в пати и в знакомых — при переводе в пати карточка переносится.
- **Раны** лечатся: healWounds помечает рану обработанной и снижает тяжесть.
- **Смерть**: здоровье 0 ставит флаг dead и состояние «мёртв».
- **Предметы** меняют зону (equipped / inventory / vault / lost) при addItems.
- **Скрытые факты** попадают в контекст ведущего как «знать, но не раскрывать».

### Ранги и опыт

- Лестница: FFF→FF→F→EEE→EE→E→DDD→DD→D→CCC→CC→C→BBB→BB→B→AAA→AA→A→S→SS→SSR.
- У героя и NPC `rank`, `rankPoints` 0–99, `rankHistory`, `rankLocked`.
- Старт героя — случайно FFF/FF/F; обычный NPC — F; уникальные D/C; боссы S/SS/SSR.
- Очки ранга даёт агент состояния (`rankGain`): 0 рутина, 1 риск, 3 квест, 5 именной враг, 10 испытание. На 100 — повышение.
- Боссы `rankLocked`: очки копятся, ранг не меняется.
- Режим опыта в кампании: `own`, `heroParty`, `even`, `dynamic`; распределяется между героем и активной пати.

## 9. Конспект

- **Только дописывание**: старый текст не переписывается и не сжимается
  повторно. Раз в 3 хода агент сжимает новый фрагмент в 4–8 пунктов и
  добавляет блок `## Арка N · ходы X–Y`.
- Факты, договорённости, долги, находки, NPC, последствия — обязательны;
  атмосфера и «вода» отбрасываются.
- Общий лимит хранения — 65 000 знаков (при переполнении режется середина,
  завязка и свежие арки остаются).
- Конспект едет в каждом запросе после истории; на 50 ходах это ~20–24 тыс.
  знаков.

## 11. Иллюстрации

- Четыре агента: герой, персонаж, предмет, сцена. Модель по умолчанию — `qwen/qwen-image-3` (endpoint `/images`), откат — Gemini. Одна картинка ~$0.03, референс +$0.003.
- **Мастер-карточка** — одна фигура в полный рост, вид спереди; портрет рисуется по ней, сцена —
  по мастер-листам героя и спутников (до трёх референсов).
- Модель по умолчанию `qwen/qwen-image-3` через `/images`; если провайдер
  её не знает — откат на `google/gemini-3.1-flash-lite-image` с флагом
  `fallback`.
- **Блок «Стиль и кадр»** — один блок, 55 тегов, 4 подгруппы:
  Стиль и сеттинг (16), Камера и композиция (13), Освещение и атмосфера (11),
  Формат и технические параметры (15). Теги идут в промт кадра, исключённые —
  в «не изображать».
- **Блок «Параметры ИИ»** — 40 опций, 5 групп и 16 секций: режим и нарратив
  (роль / темп / стиль речи), механики RPG (статы / лут / бой / квесты),
  безопасность (режим / границы / мета-команды), генерация изображений
  (режим / консистентность / фокус), память и логика (глубина / рамка /
  режиссёр). Внутри секции выбор одиночный — старые дубли гасятся.
  Хранится в `meta.aiSettings` и добавляется в промт ведущего разделом
  `# НАСТРОЙКИ ИИ`.
- Стиль иллюстраторов из мастера промтов важнее дефолтного промта.
- Кадр строится по выбранному ходу (`turn`), а не всегда по последнему; встаёт в ленту и в панель «Кадры».

## 12. Карточки персонажей

- Экспорт `⤓` — JSON формата SillyTavern V2 (`chara_card_v2`), служебные поля
  в `extensions.omika` (связь, отношение, скиллы, отношения).
- Если картинка PNG — кнопка `⤓ PNG`: JSON вкладывается в tEXt-чанок `chara`.
  Для JPEG честно возвращается 409 и предлагается JSON.
- Импорт `⤒` — диалог с dropzone, режим «знакомый / в пати», превью.
- Кнопки действий в ленте рисуются только у последних 10 ходов — старые
  сообщения не тормозят. У старых ответов остаётся кнопка `🖼`, чтобы
  нарисовать кадр именно этого хода.
- **Полная история** (`📜` в шапке игры): вся лента без обрезки, с поиском
  и картинками по ходам. Модель при этом видит только последние 24 хода и
  конспект — это разные вещи, история для игрока не режется.
- **Карты** кликабельны: открываются в модалке с зумом колесом/кнопками и
  перетаскиванием мышью.

## 13. Интерфейс

Меню: **Новая игра**, Профиль, Истории, Агенты, **Карточки**, **Ключи**,
**Ядро**, Статистика.

- **Новая игра**: название, уровень 0–11, эпоха, поле фразы + подбор агентом
  и кубиком, три блока тегов, описание мира, герой, сборка.
- **Игра**: лента, панель состояния (память, место и время, тело, деньги,
  снаряжение, фракции, карты, места, бестиарий, архив, опасная зона, конспект
  в самом низу). Кнопки «Назад», названия истории и строки «ход · место» в шапке нет.
  В шапке — стоимость, иконка состояния `▣` и меню `☰`; в меню кубик, кадр,
  размер текста, иллюстратор и история. Кубик включается подсветкой.
  Мысли героя показываются placeholder'ом в поле ввода.
  Ввод — textarea на всю ширину, высота 112px, иконка «↑» внутри правого нижнего
  угла; Enter только переносит строку, отправка — по иконке. Подсказка Enter убрана.
  При обрыве связи ход остаётся в отложенных (`omika_pending_*`) и может быть
  повторён с тем же `clientTurnId` без дубля.
- **PWA**: `manifest.webmanifest`, service worker и иконки; установка из Chrome
  Android в standalone-режиме, кнопка «Установить на телефон» в профиле.
  Тёмный `theme_color`/`background_color` — системные панели в цвет фона.
  Service worker не кэширует API, логин и навигацию.
- **Память истории** — закреплённые факты, которые ведущий помнит всегда;
  подпись в панели объясняет это игроку.
- **Карточка героя/NPC**: атрибуты, навыки и кнопка `▣ лист` — генерация
  листа персонажа спереди, сзади и погрудного портрета одним кадром.
- Под ответом: `⟳` перегенерировать, `✎` править, `‹ i/n ›` варианты, `🖼` кадр.
- **Агенты**: 8 карточек + лор-книга, переключатель игры; подпись про базовых
  и игровых агентов.
- **Ключи**: форма, список, редактирование, удаление, проверка, модели с
  ценами и фильтром.
- **Ядро**: 4 блока, ядро только для чтения, «Сохранить» и «Отменить
  изменения», подсказки агентов.
- **Статистика**: расход по агентам, кадры, кэш.

### Библиотека карточек

Раздел `#/templates` — библиотека `data/cards/`, **один JSON на карточку**:

```
data/cards/hero_000000001_kay.json
data/cards/npc_000000001_gunnar.json
```

Имя файла: `{type}_{id9}_{slug}.json`; id стабильный, 9 цифр, при переполнении
буквенный суффикс. Типы: `hero`, `npc`, `item` (включая оружие), `location`,
`faction`, `quest`, `creature`.

Общие поля: `name`, `subtitle`, `description`, `image`, `tags`, `rating`,
`gender`, `age`, `role`, `status`, `appearance`, `character`, `biography`,
`habits`, `abilities`, `attributes`, `skills`, `relations`, `equipment`,
`origin {campaignId,turn,title}`, `createdAt`, `updatedAt`.
Специфика типа — в `data` (оружие/локация/фракция/квест/тварь).

Сетка с фильтрами по типу и поиском. Действия: герой — в новую игру,
NPC — в пати/знакомые, остальные типы — следующий шаг. Кнопка
**«＋ в карточки»** сохраняет героя, NPC, предмет или локацию из игры.
Скачивание и экспорт/импорт SillyTavern убраны — только внутренняя библиотека.

API: `GET /api/cards`, `POST /api/cards`,
`POST /api/campaign/:id/save-card`.

### Опасная зона

В панели игры (раскрывающийся блок) три действия с подтверждением:
«Сбросить настройки игры» (агенты/промты/арт к глобальным), «Начать
прохождение заново» (состояние к ходу 0, история, конспект, архив и снимки
очищаются), «Удалить прохождение» (кампания целиком). API:
`POST /api/campaign/:id/reset`, `POST /api/campaign/:id/restart`,
`DELETE /api/campaign/:id`.

### Контейнер игры

В «Историях» у каждой игры есть кнопка **«Просмотреть»** (между статусом и
«Продолжить»). Открывается `#/view/<id>` — изолированный контейнер игры:

- **Агенты игры** — все восемь агентов с моделью, температурой, вкл/выкл и
  полным промтом (раскрывающийся блок). Промты берутся из снапшота кампании,
  поэтому не меняются от других игр.
- **Герой** — карточка с аватаром/инициалом, здоровьем, деньгами, ранами,
  состояниями, интуицией и полосами скиллов.
- **Спутники и NPC** — человеческие карточки: имя, роль, статус, отношение,
  связь, «в сцене», внешность, характер, одежда, прошлое, заметка, отношения,
  скиллы полосами, экспорт карточки.
- **Задания** — статус (active/failed/done), срок и шаги.
- **Локации** — известные места с заметками.
- **Фракции** — отношение, глава, тень, состав, заметка.
- **Карточки предметов** — имя, количество, где лежит, заметка.
- **Конспект** — память истории, скользящий конспект и замороженный конспект
  текущего окна.
- **Галерея** — все сгенерированные изображения этой игры с подписями и
  номером хода; клик открывает кадр в новой вкладке.

Страница собирается из `/api/campaign/:id` и `/api/agents?id=:id`, поэтому
работает и на старом сервере без отдельной ручки.

## 17. Ограничения

- OpenRouter: Seedream 5.0 Flash недоступен; Qwen Image 3 работает через
  `/images` (не через chat/completions).
- Gemini отдаёт JPEG, поэтому PNG-карточки доступны только для PNG-картинок.
- Встроенного контент-фильтра нет (см. границу выше); NSFW-теги не являются
  разрешением на сцены с несовершеннолетними.
- Ядро (~112 тыс. знаков) грузится целиком; кэш снижает цену, но не размер окна.
- Карта места детерминирована от названия: пока герой в той же локации,
  рисунок не меняется.
- Запрос картинки ограничен таймаутом: при зависании провайдера игра не ждёт вечно.
- Конспект растёт (~120 знаков на ход); при переполнении режется середина,
  завязка и свежие арки остаются, вытесненные арки уходят в архив.

## Хостинг

Один Node-процесс, состояние в `data/`. В комплекте `Dockerfile`,
`docker-compose.yml`, `.env.example` и `docs/DEPLOY.md`:

- `HOST=0.0.0.0` для контейнера, локально по умолчанию `127.0.0.1`;
- том `omika-data` хранит кампании, картинки и трейсы;
- снаружи обязателен HTTPS reverse proxy; встроенная авторизация уже есть,
  Basic Auth — только как второй слой; поддерживается Cloudflare Tunnel;
- один инстанс: JSON-файлы и сессии в памяти нельзя масштабировать
  горизонтально без переезда на БД;
- бэкап — архив тома `data/` перед обновлением.
