# ТЗ: Omika — текстовая RPG в браузере

Документ описывает всё, что есть в проекте: блоки, агентов, теги, правила,
механики, интерфейс, API и ограничения. Версия — по состоянию сборки.

---

## 1. Что это

Локальная текстовая RPG: игрок ведёт героя, ведущий-модель пишет сцену,
агент состояния обновляет цифры, конспектировщик дописывает хронику по аркам,
иллюстраторы рисуют кадры. Всё работает через OpenRouter API или совместимый
провайдер, данные лежат файлами в `data/`, сервер — нативный Node без
зависимостей.

Запуск: `node src/server.ts` → `http://127.0.0.1:7801`.

---

## 2. Четыре блока истории

1. **ЯДРО** — `data/source/core.md` (~112 тыс. знаков). Правила мира и
   повествования. **Не изменяется**: сервер отклоняет правку (403), в
   интерфейсе поле только для чтения. Одно на все игры, в файл кампании не
   копируется, подставляется при загрузке.
2. **ТОН** — **промт для промта**: `data/source/tone-prompt.md`. По нему
   мастер собирает тон конкретной игры. Редактируется во вкладке «Ядро».
3. **МИР** — **промт для промта**: `data/source/world-prompt.md`. По нему
   собирается мир игры. Редактируется во вкладке «Ядро».
4. **ГЕРОЙ** — `data/source/hero-prompt.md` + форма игрока; `POST
   /api/generate/hero` собирает блок агентом.

Тон, мир и герой для каждой игры генерируются отдельно и хранятся в
кампании. Старые шаблоны тона и мира сохранены как `*.prev.md`.

Все четыре блока склеиваются в стабильный блок контекста и стоят первыми —
на этом держится кэш провайдера.

## 3. Агенты

| Агент | Роль | По умолчанию |
|---|---|---|
| `gm` | ведущий: пишет сцену | включён |
| `prompter` | мастер промтов: тон, мир, герой, теги, промты игры | включён |
| `state` | состояние: предметы, квесты, NPC, фракции, лор, время | включён |
| `summarizer` | хроника по аркам | включён |
| `artistHero` | мастер-лист героя | включается в игре |
| `artistNpc` | карточка персонажа | включается в игре |
| `artistItem` | карточка предмета | включается в игре |
| `artistScene` | кадр сцены | включается в игре |

- У каждого: модель, температура, лимит токенов, промт, включение, кнопка
  «Тест», выбор ключа API.
- Глобальные настройки — шаблон. **При создании игры создаются свои ведущий
  и иллюстратор истории**: мастер промтов собирает `gmPrompt`, температуру
  и стилевые промты художников, они сохраняются в `agents` и `meta.prompts`
  кампании. Остальные агенты берутся из базы.
- Схема агентов — версия 13. При миграции обновляются промт конспектировщика
  и лимит токенов.
- Хранятся в `data/agents.json`.

## 4. Теги

### 4.1. Каталог

**239 тегов, 3 группы.** Собирается `node scripts/build-catalog.mjs`.

| Группа | Тегов | Подгруппы |
|---|---:|---|
| Жанры и стиль | 149 | Жанры и поджанры (55), Эмоции и тон (28), Демография (6), Литературные направления (12), Формы повествования (16), Миры и сеттинги (32) |
| Контент-теги (18+ и зрелый контент) | 74 | Тёмное (24), Психология и зависимости (10), Зрелые и социальные темы (29), Специфические триггеры (11) |
| Тип повествования | 16 | Роль ИИ (3), Темп (3), Стиль речи (3), Безопасность и границы (4), Мета-команды (3) |

- У каждого тега есть **всплывающая подсказка** с коротким смыслом.
- Каталог жанров — авторский файл `data/genre-catalog.json`; контент —
  `data/content-catalog.json`; тип повествования — `data/narrative-catalog.json`.
  При сборке эти группы заменяются целиком, старые имена попадают в
  `data/removed-tags.json` для аудита.
- Эпоха задаётся не тегами, а бегунком (см. 4.3).

### 4.2. Как выбираются

Каждый тег — кнопка с тремя состояниями: пусто → **выбрать** (✓) →
**исключить** (✕) → пусто. Внизу сводка выбранного и исключённого.
У каждой подгруппы кнопки «все», «исключить», «сброс».

- **Поиска по тегам нет** — вместо него поле фразы.
- **Поле фразы**: «Опиши игру: романтическая комедия, жёсткое фэнтези…».
- **«Подобрать»** — агент-мастер получает фразу, уровень и весь список тегов,
  возвращает все подходящие (до 400, клиент просит 150). Примеры:
  «романтическая комедия» → романтика, комедия, эмоции, сёдзё, повседневность;
  «максимально жёсткое фэнтези» → тёмное фэнтези, пытки, казни, геноцид,
  инквизиция, ПТСР, абьюз, мрачное, ангст.
- **Кубик 🎲 у поля** — случайная выборка из того, что агент считает
  подходящим (45/60/75 по уровню); пустая фраза — случайные по уровню.
- **Кубик 🎲 у уровня** — локальный подбор набора под уровень (см. 5).
- Стоимость подбора фразы ~$0,0003–0,0008, время 1–3 с.

### 4.3. Эпоха

- Бегунок от −10 000 до +999 999 999, центр шкалы — 2000-е.
- Влево прошлое линейно, вправо будущее по логарифмической шкале.
- Рядом поле ручного ввода года (до 9 знаков), синхронизировано с бегунком.
- Значение уходит в генерацию тона строкой `Эпоха: …` и в мету кампании
  (`epochYear`).

## 5. Уровень повествования (0–11)

Ползунок в «Новой игре», рядом кубик подбора тегов. Значение хранится в мете
кампании (`toneLevel`) и директивой уходит в блок тона.

| Уровень | Название |
|---:|---|
| 0 | Сказка для детей |
| 1 | Уютное фэнтези |
| 2 | Доброе приключение |
| 3 | Классическое фэнтези |
| 4 | Мрачное фэнтези |
| 5 | Тёмное фэнтези |
| 6 | Жёсткое тёмное фэнтези |
| 7 | Жестокость и кровь |
| 8 | Убийства и расчленение |
| 9 | Жертвоприношения и культы |
| 10 | За гранью |
| 11 | Максимум без смягчений |

- Кубик у уровня: 22 / 28 / 34 / 42 / 52 тега по диапазонам, тёмное
  добавляется с 5-го уровня, контент 18+ — с 5–6-го.
- **Граница:** сексуальное насилие не описывается ни на одном уровне.
  Явные сексуальные сцены проектом не генерируются; соответствующие теги —
  рамки настроек, а не разрешение.

## 6. Создание игры

Шаги мастера: **1) Тон и мир → 2) Герой → 3) Сборка**.

1. Название, описание мира, теги, уровень, эпоха.
2. Тон генерируется по тегам и уровню; мир — по описанию.
3. Герой: шаблоны + свои поля, генерация агентом.
4. Сборка: проверка и создание кампании.

При создании сервер сам вызывает мастера промтов и сохраняет в игру:

- промт ведущего и температуру;
- промты иллюстраторов (герой, персонаж, предмет, сцена);
- `meta.prompts`, `meta.tags`, `meta.toneLevel`, `meta.epochYear`.

Создание занимает ~6–9 с (один дополнительный вызов модели), стоимость
~$0,001–0,002.

## 7. Ход игры

1. Контекст собирается **до** изменения состояния (чтобы кэш считался верно).
2. Ведущий пишет сцену — потоком (SSE) или обычным ответом.
3. Параллельно: агент состояния правит цифры, конспектировщик дописывает
   хронику (раз в 3 хода).
4. Ответ сохраняется со снимком хода (откат, перегенерация, варианты).

Слои контекста: статика (ядро+тон+мир+герой) → настройки ИИ → память →
арки → история (окно 30 ходов, сдвиг блоками по 20) → конспект → состояние →
лор-книга → заметки → ход игрока.

**Время:** если ведущий не сдвинул часы, сервер сам добавляет +1 час с
переходом через сутки. Время всегда идёт.

## 8. Механики

- **Кубик d36** (галочка 🎲 у ввода): 36 граней, 34 — джокер удачи (+10),
  35 — судьба (переброс), 36 — бездна (−10). Результат — карточкой в ленте.
- **Скрытые проверки**: 8 скиллов (Сила, Ловкость, Скрытность, Воля,
  Восприятие, Красноречие, Знание, Выживание), значения 0–20, бросок d36
  против сложности. Игрок видит последствия, не цифры.
- **Мысли героя**: строка интуиции и страхов под лентой, агент обновляет.
- **Фракции**: карточки с главой, серым кардиналом и составом, скрытые члены.
- **Квесты** со сроком в ходах: просрочка закрывает дело, пишет в архив и
  оставляет крючок.
- **Архив**: выполнено, брошено, потеряно, выброшено — не удаляется.
- **Лор-книга**: записи с ключами, в контекст попадают только совпавшие;
  автолор заводит записи о новых местах, фракциях и тварях.
- **Память истории**: закреплённые игроком факты, идут в каждый промт.
- **Отношения в пати**: агент заполняет при напряжении, ревности, тепле.
- **Крючки** дедуплицируются по смыслу и ограничены 30 штуками; вытесненные уходят в архив.\n- **Раны** лечатся: healWounds помечает рану обработанной и снижает тяжесть.\n- **Смерть**: здоровье 0 ставит флаг dead и состояние «мёртв».\n- **Предметы** меняют зону (equipped / inventory / vault / lost) при addItems.\n- **Скрытые факты** попадают в контекст ведущего как «знать, но не раскрывать».

## 9. Конспект

- **Только дописывание**: старый текст не переписывается и не сжимается
  повторно. Раз в 3 хода агент сжимает новый фрагмент в 4–8 пунктов и
  добавляет блок `## Арка N · ходы X–Y`.
- Факты, договорённости, долги, находки, NPC, последствия — обязательны;
  атмосфера и «вода» отбрасываются.
- Общий лимит хранения — 24 000 знаков (обрезается только хвост при
  переполнении, старые арки не пересобираются).
- Конспект едет в каждом запросе после истории; на 50 ходах это ~6–8 тыс.
  знаков.

## 10. Карты

- **Карта места** — рогаликовая ASCII: комнаты, коридоры, двери, предметы
  `$ * !`, твари `V W x`, спавн `@`. Детерминирована от названия места,
  31×14 (`src/core/dungeon.ts`).
- **Карта мира** — континент, леса, горы, болота, пины локаций и легенда;
  неизведанное помечено `?`. Детерминирована от названия мира
  (`src/core/worldmap.ts`). Если локаций ещё нет, пином ставится текущее место.
- Обе карты в панели: место выше, мир ниже. Символы крупные (11px в панели,
  14px в модалке), без лигатур.
- Клик открывает модалку: зум колесом и кнопками, перетаскивание,
  `Esc`/клик мимо — закрыть. На телефоне карты свёрнуты в `<details>`.

## 11. Иллюстрации

- Четыре агента: герой, персонаж, предмет, сцена.
- **Мастер-карточка** — референс персонажа; портрет рисуется по ней, сцена —
  по мастер-листам героя и спутников (до трёх референсов).
- Модель по умолчанию `bytedance/seedream-5.0-flash`; если провайдер её не
  знает — откат на `google/gemini-3.1-flash-lite-image` с флагом `fallback`.
- **Блок «Стиль и кадр»** — один блок, 55 тегов, 4 подгруппы:
  Стиль и сеттинг (16), Камера и композиция (13), Освещение и атмосфера (11),
  Формат и технические параметры (15). Теги идут в промт кадра, исключённые —
  в «не изображать».
- **Блок «Параметры ИИ»** — 40 опций, 5 групп и 16 секций: режим и нарратив
  (роль / темп / стиль речи), механики RPG (статы / лут / бой / квесты),
  безопасность (режим / границы / мета-команды), генерация изображений
  (режим / консистентность / фокус), память и логика (глубина / рамка /
  режиссёр). Внутри секции выбор одиночный — старые дубли гасятся.
  Хранится в `meta.aiSettings` и добавляется в промт ведущего разделом
  `# НАСТРОЙКИ ИИ`.
- Стиль иллюстраторов из мастера промтов важнее дефолтного промта.
- Кадр встаёт в ленту и в панель «Кадры».

## 12. Карточки персонажей

- Экспорт `⤓` — JSON формата SillyTavern V2 (`chara_card_v2`), служебные поля
  в `extensions.omika` (связь, отношение, скиллы, отношения).
- Если картинка PNG — кнопка `⤓ PNG`: JSON вкладывается в tEXt-чанок `chara`.
  Для JPEG честно возвращается 409 и предлагается JSON.
- Импорт `⤒` — диалог с dropzone, режим «знакомый / в пати», превью.
- Кнопки действий в ленте рисуются только у последних 10 ходов — старые
  сообщения не тормозят.

## 13. Интерфейс

Меню: **Новая игра**, Профиль, Истории, Агенты, **Ключи**, **Ядро**, Статистика.

- **Новая игра**: название, уровень 0–11, эпоха, поле фразы + подбор агентом
  и кубиком, три блока тегов, описание мира, герой, сборка.
- **Игра**: лента, панель состояния (память, место и время, тело, деньги,
  снаряжение, фракции, карты, места, бестиарий, архив), быстрые действия,
  мысли, ввод с кубиком.
- Под ответом: `⟳` перегенерировать, `✎` править, `‹ i/n ›` варианты, `🖼` кадр.
- **Агенты**: 8 карточек + лор-книга, переключатель игры; подпись про базовых
  и игровых агентов.
- **Ключи**: форма, список, редактирование, удаление, проверка, модели с
  ценами и фильтром.
- **Ядро**: 4 блока, ядро только для чтения, «Сохранить» и «Отменить
  изменения», подсказки агентов.
- **Статистика**: расход по агентам, кадры, кэш.

### Контейнер игры

В «Историях» у каждой игры есть кнопка **«Просмотреть»** (между статусом и
«Продолжить»). Открывается `#/view/<id>` — изолированный контейнер игры:

- **Агенты игры** — все восемь агентов с моделью, температурой, вкл/выкл и
  полным промтом (раскрывающийся блок). Промты берутся из снапшота кампании,
  поэтому не меняются от других игр.
- **Карточки предметов** — имя, количество, где лежит, заметка.
- **Конспект** — память истории, скользящий конспект и замороженный конспект
  текущего окна.
- **Галерея** — все сгенерированные изображения этой игры с подписями и
  номером хода; клик открывает кадр в новой вкладке.

Страница собирается из `/api/campaign/:id` и `/api/agents?id=:id`, поэтому
работает и на старом сервере без отдельной ручки.

## 14. API (кратко)

```
GET  /api/catalog            теги (3 группы)
GET  /api/tone-levels        шкала 0–11

POST /api/generate/hero      герой {form, toneLevel}
POST /api/tags/suggest       теги по фразе {description, level, limit}
GET/PUT /api/blocks          ядро (только чтение) и глобальные промты
GET/POST/PUT/DELETE /api/keys        ключи API
POST /api/keys/test          проверка ключа
GET  /api/keys/:id/models    модели и цены
GET/PUT /api/lorebook        лор-книга
GET  /api/campaigns          список
POST /api/campaigns          создать (сам собирает промты игры)
GET  /api/campaign/:id       состояние, история, карты, конспект, снимки
POST /api/campaign/:id/turn      ход {input, dice}
POST /api/campaign/:id/stream    ход потоком (SSE)
POST /api/campaign/:id/regenerate|edit|variant
POST /api/campaign/:id/image     кадр {mode: scene|portrait|card|item|hero}
POST /api/campaign/:id/card      импорт карточки V2
GET  /api/campaign/:id/card      экспорт (JSON или PNG)
POST /api/campaign/:id/memory    память истории
POST /api/campaign/:id/drop      выбросить предмет
GET/PUT /api/campaign/:id/art    теги стиля и параметры ИИ
GET/PUT /api/campaign/:id/prompts промт ведущего и температура
GET  /api/agents, PUT /api/agents/:id
```

## 17. Ограничения

- OpenRouter: Seedream 5.0 Flash в каталоге нет — откат на Gemini.
- Gemini отдаёт JPEG, поэтому PNG-карточки доступны только для PNG-картинок.
- Явные сексуальные сцены не генерируются (ограничение проекта).
- Ядро (~112 тыс. знаков) грузится целиком; кэш снижает цену, но не размер окна.
- Карта места детерминирована от названия: пока герой в той же локации,
  рисунок не меняется.
- Запрос картинки ограничен таймаутом: при зависании провайдера игра не ждёт вечно.\n- Конспект растёт (~120 знаков на ход); при переполнении режется хвост,
  старые арки не пересобираются.

## Инструменты разработки

- `scripts/dev.mjs status|start|stop|restart` — управление сервером на порту
  7801 (или `PORT`), лог в `data/dev-server.log`.
- `scripts/shot.mjs "/#/route" name` — скриншот страницы через Playwright,
  вывод в `.shots/name.png` плюс ошибки консоли.
- `tsconfig.json` — проверка типов `tsc --noEmit` (строгий режим выключен,
  но контракты агентов и состояния проверяются).
- `eslint.config.js` + `.prettierrc.json` — линт JS и скриптов, форматирование.
- `tools/duckdb/duckdb.exe` — SQL по кампаниям:
  `SELECT meta.title, state.turn FROM read_json_auto('data/campaigns/*.json')`.
- Трейсы ходов: `data/traces/YYYY-MM-DD.jsonl` — полный запрос к модели,
  сегменты, токены и цена; отключается `OMIKA_TRACE=0`.
- Локальный git: два коммита, remote `git@github.com:OkiNamura/RPG.git`.
