# Omika — текстовая RPG в браузере

Игра, где ведущий — модель, а память — отдельный процесс: состояние в JSON,
конспект append-only, критик проверяет каждый ход.

## Запуск

```bat
start.cmd
```

или

```bash
node src/server.ts
```

Открой **http://127.0.0.1:7801**

Порт можно сменить: `set PORT=8080` перед запуском.

## Что внутри

```
src/
  server.ts       — HTTP-сервер: статика + API, сессии в памяти
  web/
    index.html    — страница
    style.css     — тёмная тема, колонка повествования + панель состояния
    app.js        — клиент без фреймворков
  core/
    state.ts      — состояние кампании (единственный источник правды о цифрах)
    context.ts    — сборка контекста по слоям (статика → конспект → история → стейт)
    conspect.ts   — конспект, append-only: закрытые арки не переписываются
    delta.ts      — разбор и применение изменений состояния
    critic.ts     — дешёвые проверки ответа (без модели)
    model.ts      — интерфейс модели + мок
    openrouter.ts — клиент OpenRouter: reasoning off, структурный вывод
    turn.ts       — цикл одного хода
    storage.ts    — сохранение и загрузка кампании (JSON)
  start/
    texts.ts      — заготовки ядра, мира и тона
    assemble.ts   — сборка кампании по тегам (заглушка, M2)
data/campaigns/   — сохранённые кампании (JSON)
docs/             — архитектура и этапы
```

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/catalog` | теги тона (пресетов мира нет) |
| POST | `/api/generate/tone` | тон по выбранным тегам `{selections}` |
| POST | `/api/generate/world` | мир из описания `{description, title}` |
| GET | `/api/campaigns` | список кампаний |
| POST | `/api/campaigns` | создать `{id, tone, world, hero, meta}` |
| GET | `/api/campaign/:id` | состояние + история + конспект |
| POST | `/api/campaign/:id/turn` | ход `{input}` → проза, изменения, стейт |
| POST | `/api/campaign/:id/stream` | тот же ход потоком (SSE: `delta` / `done`) |
| POST | `/api/campaign/:id/regenerate` | перегенерировать ход `{turn}` |
| POST | `/api/campaign/:id/edit` | правка реплики `{turn, input}` |
| POST | `/api/campaign/:id/variant` | переключить вариант `{turn, index}` |
| POST | `/api/campaign/:id/image` | кадр сцены или портрет `{mode: "scene" \| "portrait", name?}` |
| POST | `/api/campaign/:id/drop` | выбросить предмет `{name}` |
| POST | `/api/campaign/:id/quest` | задача: `{title, action: "done" \| "abandon"}` |
| GET | `/api/stats` | агрегат: ходы, токены, кэш, деньги |
| GET | `/api/agents` | настройки восьми агентов |
| PUT | `/api/agents/:id` | изменить агента `{model, temperature, maxTokens, prompt, enabled}` |
| POST | `/api/agents/:id/reset` | сбросить к заводским |
| POST | `/api/agents/:id/test` | прогнать агента на пробном вводе `{input}` |
| DELETE | `/api/campaign/:id` | удалить |

## Память и окно

В контекст уходят только: промт ведущего (неизменное ядро + тон), мир,
карточка героя, **последние 24 хода**, скользящий конспект всего, что старше,
служебный блок состояния и сам ход.

```
[промт ведущего: ядро+тон]  ← не меняется, кэшируется
[мир] + [герой]             ← рядом с ядром, не меняются
[последние 24 хода]         ← дописываются, сдвиг блоками по 20 ходов
[конспект прошлого]         ← агент дописывает арку раз в 3 хода
[состояние]                 ← цифры и карточки
[ход игрока]
```

Окно сдвигается **блоками**, а не по сообщению: иначе префикс менялся бы
каждый ход и кэш умирал бы ровно на длинной истории. Конспект ограничен
6 000 знаков, поэтому контекст не растёт с длиной кампании.

## Агенты

Восемь ролей, у каждой свои модель, температура и промт (`data/agents.json`).

**У каждой игры свои агенты.** При создании кампании набор копируется в её
файл: правки в игре не трогают глобальные настройки и наоборот. На странице
«Агенты» есть переключатель «Чьи настройки правим» — глобальные или конкретная
игра. Старые кампании без своего набора работают на глобальном.

| Агент | Что делает |
|---|---|
| `gm` | ведущий: пишет сцену, тон уже вшит в его промт |
| `prompter` | мастер промтов: собирает тон, мир и героя из тегов и уровня |
| `state` | хранитель сохранения: инвентарь, задачи, NPC, места, крючки |
| `summarizer` | хроника по аркам: раз в 3 хода дописывает новый фрагмент |
| `artistHero` | мастер-лист героя |
| `artistNpc` | карточка персонажа |
| `artistItem` | карточка предмета |
| `artistScene` | кадр сцены |

Мастер промтов включён по умолчанию: генерация тона и мира идёт через него
(его модель, температура и промт), а `/api/generate/hero` собирает героя
в JSON-поля формы. Остальные четыре блока по-прежнему склеиваются напрямую.

Модель рисования по умолчанию — `qwen/qwen-image-3` (endpoint `/images`).
Если провайдер её не отдаёт, сервер честно откатывается на
`google/gemini-3.1-flash-lite-image` и возвращает `fallback: true` вместе
с именем фактической модели.

Правятся на странице **Агенты**: промт, модель, температура, лимит токенов,
включение, кнопка «Тест» с пробным вводом и стоимостью.

## Новая игра

Отдельный пункт меню **«＋ Новая игра»** — конструктор: название, **уровень
повествования**, теги тона, мир, герой, обзор.

**Уровень повествования** — ползунок 0–11: 0 «Сказка для детей», 5 «Тёмное
фэнтези», 8 «Убийства и расчленение», 11 «Максимум без смягчений». Рядом
кубик 🎲 подбирает теги под выбранный уровень: на 0–2 — доброе и уютное,
на 7–8 — кровь и убийства, на 9–11 — культы и предел. Новый бросок заменяет
прежний набор. Уровень попадает в мету кампании и
директивой в блок тона: на 0–2 смерть и кровь не описываются, на 7–9 сцены
физиологичны. Явные сексуальные сцены шкала не разрешает ни на одном уровне —
взрослые темы идут намёком и последствиями.

**Подбор тегов по словам** — поле под поиском: несколько слов через запятую,
кнопка «Подобрать» ставит все совпадения (по названию и подсказке), кубик 🎲
выбирает 3–6 случайных из найденных.

**Теги иллюстратора** — отдельный сворачиваемый блок в конструкторе: 55 тегов в 4 подгруппах (стиль, камера, свет, формат),
с выбором «выбрать / исключить / сброс».

На шаге мира мир описывается своими словами: готовых пресетов нет, описание
уходит в генератор (`POST /api/generate/world {description}`).

У каждого тега есть всплывающая подсказка: «что тег значит и что даёт» —
644 описания в `data/tag-descriptions.json`.

## Кнопки под ответом и откаты

Под каждым ответом ведущего: `⟳` перегенерировать, `✎` править реплику,
`‹ 1/2 ›` варианты, `🖼` кадр.

Основа — **снимок после каждого хода** (`TurnSnapshot` в файле кампании):
состояние, конспект и текст. Перегенерация откатывает состояние к ходу `N−1`,
повторяет ввод и сохраняет прежний ответ вариантом. Правка делает то же
с новым текстом. Переключение варианта меняет состояние на сохранённое —
то есть это честная ветка, а не подмена текста.

Отсюда же бесплатно получается удаление части истории: восстановить снимок
хода `N−1`, обрезать лог и снимки. Конспект откатится вместе со снимком,
потому что он в него входит.

## Карточки, карты, компоновка

- **Мастер-карточка** — референсное изображение героя, персонажа или предмета.
  Она генерируется один раз и передаётся модели как входная картинка при
  рисовании портретов и сцен: `mode: "card" | "hero" | "item"`. Портрет
  рисуется по мастер-листу, сцена — по мастер-листу героя и спутников
  (до трёх референсов). Так внешность не «плывёт» между кадрами.
- **Карточки локации** — полоса снизу: кто есть в сцене, по клику
  раскрывается карточка в панели.
- **Перенос карточек** — кнопка `⤓` в карточке персонажа отдаёт JSON в формате
  SillyTavern V2 (`chara_card_v2`): имя, описание, характер, сценарий, роль,
  а служебные поля (связь, отношения, отношение) — в `extensions.omika`.
  Если картинка в PNG — кнопка `⤓ PNG` кладёт тот же JSON внутрь файла
  в tEXt-чанок `chara` (`src/core/png.ts`). Импорт — кнопка `⤒`: диалог
  с dropzone, выбором «знакомый / в пати» и превью.
- **Лор-книга** (World Info) — записи с ключевыми словами: в контекст попадают
  только те, чей ключ встретился в месте, реплике или прошлом ответе. Контекст
  не растёт вместе с миром. Правится на странице «Агенты», хранится в
  `data/lorebook.json`, ключи ищутся с грубым учётом склонений.
- **Новые карточки** появляются в ленте сами: когда агент впервые заводит
  персонажа, клиент показывает врезку с именем, ролью и внешностью.
- **Карты убраны из игры.** ASCII-карта места и карта мира вынесены в архив
  `../archive/omika-maps/` (код, тесты, README). Вернуть можно отдельным
  блоком или иллюстрацией — это в планах.
- **Карточки персонажей в игре** — сетка 3 колонки: имя, роль, маленькая
  картинка. Клик открывает карточку с описанием, характером, способностями,
  навыками и кнопками «в полный рост» / «портрет».
- **Кубик d36** — галочка 🎲 у поля ввода: 36 граней, 34/35/36 — джокеры
  (удача +10, судьба — переброс, бездна −10). Результат — карточкой в ленте:
  джокеры золотом, «бездна» кровью.
- **Скрытые проверки** — `src/core/skills.ts`: 8 скиллов у героя и NPC,
  бросок d36 против сложности. Игрок видит только последствия, не цифры.
- **Мысли героя** — строка интуиции и страхов под лентой, агент состояния
  заполняет `intuition` каждый ход.
- **Фракции** — карточки с главой, серым кардиналом и составом; скрытые
  члены помечены.
- **Библиотека карточек** — `data/cards/`, один JSON на карточку: герой, NPC, предмет/оружие, локация, фракция, квест, тварь. Сетка с фильтрами, карточка героя открывается как шаблон новой игры.
- **Память истории** — блок в панели: закреплённые факты идут в контекст
  каждый ход (`POST /api/campaign/:id/memory`).
- **Автолор** — агент состояния пишет `lore`, а новые места, фракции и твари
  попадают в лор-книгу сами.
- **Теги** — 239 тегов в 3 группах — игровые. Теги иллюстратора (55 в 1 группе, 4 подгруппы) живут отдельно, у агента. Глобальная дедупликация: один тег
  живёт в одной группе, даже если встречался в нескольких (было 103 повтора).
  «Жанры (доп.)» слиты в «Жанры», «Сеттинг» — в «Сеттинг и атмосфера», теги рисования вынесены из игрового каталога: у иллюстратора свои 55 тегов в одном блоке «Стиль и кадр». Добавлена «Точка зрения» — от первого лица, глазами врага и т.д.
  Каждая группа разбита на подкатегории (у «Персонажей» — ГГ: раса, класс,
  сила, место и мир, чувства и идеи, предметы; у сюжета — силы и системы,
  снаряжение, существа, структура, конфликты). Есть поиск по названию и
  описанию. Блоки — выпадающие, у тега три состояния: пустой квадрат,
  зелёная галочка, красный крест.
- **Теги иллюстратора** — отдельный блок из 53 тега в 3 группах (стиль,
  адаптация, камера, свет, материалы, окружение, персонаж, предмет, техника).
  Живут на странице «Агенты», дополняют промт кадра и попадают в «не изображать».
- **Карточки сцены** — внизу только те, кто реально в кадре: агент состояния
  ставит `present: true/false`.

## Четыре блока

Порядок и назначение — как в исходной архитектуре:

1. **ЯДРО** — `data/source/core.md`, ~112 тыс. знаков. Одно на все игры, не меняется.
   В файл кампании не пишется: подставляется при загрузке.
2. **ТОН** — генерируется по тегам при создании (`Тон v1` + 644 тега).
3. **МИР** — генерируется из описания игрока (`Промт миры v6`). Предустановленных
   миров нет: каталог пресетов удалён вместе с исходником `world-presets.txt`.
4. **ГЕРОЙ** — собирается из формы мастера.

Все четыре склеиваются в один стабильный блок контекста и стоят первыми,
поэтому кэш провайдера работает: ход на 45k токенов стоит ~$0.00013 вместо $0.002.

Пересобрать каталог из исходников: `node scripts/build-catalog.mjs`.

## Стрим и картинки

- **Стрим.** Ход идёт через `/stream`: ведущий пишет прозу, клиент показывает
  её по мере генерации. Первый кусок приходит через ~3 с вместо ожидания всего ответа.
- **Иллюстратор.** Модель по умолчанию — `qwen/qwen-image-3` (откат —
  Gemini). Кадр сцены строится по выбранному ходу, с описанием места, героя
  и присутствующих NPC; стилевые теги идут в начало промта. Кадры кликабельны.
  Одна картинка стоит ~$0.03; Qwen Image 3 работает через `/images`, референсы — +$0.003 за штуку.
- **Карточка персонажа.** Одна фигура в полный рост, вид спереди; портрет —
  отдельно. Кнопки в карточке: «в полный рост» и «портрет».
- **Карты.** Убраны из игры, код и тесты — в `../archive/omika-maps/`.
- **Сроки задач.** У задачи есть `turnsLimit` в ходах; просрочка закрывает её,
  пишет в архив и оставляет крючок «Просрочено».
- **Статистика.** Отдельно считается расход по агентам (ведущий, состояние,
  конспект, иллюстратор) и число кадров.

## Принципы

1. **Проза — для игрока, стейт — для правды.** Деньги, предметы, раны, долги живут в JSON.
2. **Конспект производный.** Источник истины — лог. Конспект кэширует смысл.
3. **Арки не переписываются.** Добавляем новую — старая заморожена.
4. **Порядок контекста фиксирован.** Стабильный префикс = попадание в кэш = дешевле ход.
5. **Проверка дешёвая.** Сначала детерминированные правила, модель-критик — позже.

Подробнее — `docs/ARCHITECTURE.md`, этапы — `docs/ROADMAP.md`.

`Dockerfile`, `docker-compose.yml`, `.env.example` и инструкция

## Ключ

`OPENROUTER_API_KEY` лежит в `.env` (в git не попадает). Ключ читает только
сервер, в браузер он не уходит.
